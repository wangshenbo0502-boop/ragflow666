# 轨知 RailMind 前端微调指导书

> 更新：2026-11-14 · 适用目录：`web/`
>
> **目标：保持现在的布局与黑白两套配色，让阅读、输入和点击更舒服。**
>
> 本次只更新指导书，不修改前端代码。下面的数值是基于当前样式提出的小范围试调值，尚未经过浏览器效果验收。

## 1. 调整边界：原来的界面继续作为基准

保留当前顶部导航、首页大标题、章节编号、提问区位置、知识展示、档案插画和资料来源。各区块的前后顺序、左右关系与功能入口保持不变。

本轮要做到：老用户进来依然认识这个页面，使用时感觉更顺手。

| 保留原样 | 允许微调 |
| --- | --- |
| 顶部品牌、居中主导航、右侧工具区 | 图标与文字对齐、必要的点击范围和焦点反馈 |
| 首页品牌大标题和介绍区 | 确有拥挤时，小幅调整字号或文字间距 |
| 左侧章节标记、右侧提问区域 | 区域内部的留白、控件边线与文字层级 |
| 提问框下面的准备折叠区 | 摘要可读性、当前状态说明、展开后的排列 |
| 知识与档案展示、滚动插画 | 必要的遮挡修复和减少动态效果支持 |
| 知识库与问答的现有列表 | 行内间距、长文本、操作区稳定性 |
| 当前明暗主题、字体、图标、按钮形状 | 使用既有颜色变量，完善交互状态 |

明确排除：新增全局侧栏、改成仪表盘、调整首页模块顺序、把准备状态搬到右侧面板、删除展示章节、强行把所有操作塞进首屏、全站换圆角和阴影、重新设计品牌。

页面和 RAGFlow 的差异继续来自现有轨知品牌、铁路场景、线稿与内容组织。本轮不以“更不一样”为理由重排布局。

## 3. 第一轮只做这五类细节

### 3.1 输入区内部对齐

这是优先级最高、最不影响原有风格的一项。

当前桌面样式中，输入文字左右内边距为 26px，底部工具区左右边距为 22px，设备字段左右内边距为 24px。三条边线相差不大，但可以统一到 24px：

- 输入正文的起点与底部知识库选择起点对齐。
- 设备字段的左右边线与输入正文保持一致。
- 开始按钮的右边线与正文右边界对齐。
- 手机按现有约 16px 的内边距处理，不继承桌面的 24px。
- 保留输入框默认 180px 高度、可拖动调整高度与当前边框、底色、圆角。
- 保留知识库选择与提交按钮处于底部同一行。

这里先改现有样式即可，不需要重新封装提问组件，也不改变表单布局。

**验收：** 四个场景切换后边线一致；展开设备字段、选择长知识库名时，按钮仍在稳定位置。

### 3.2 让操作状态容易读到

准备区继续留在提问框下方，保留折叠方式。

- 状态、错误等实际需要阅读的信息，如果 12px 偏小，可试调到 13px。
- 章节英文编号等装饰文字保持当前大小，不整体放大所有辅助文字。
- “为什么不能开始对话”的现有提示继续紧邻输入区，不只依赖按钮变灰。
- 折叠摘要中的文字与箭头垂直居中；较窄时允许文字合理换行。
- 摘要保持简短，详细的模型、文件状态留在展开内容中。
- 请求中、无资料、未配置、解析失败按真实状态显示；不能把请求失败写成正常的“0 份资料”。

页面已有禁用原因、导入进度和失败提示，先确认现有实现是否足够。仅在确实难以理解时改措辞，不新增一套状态逻辑。

**验收：** 不展开所有内容，也能理解当前能否开始；需要处理问题时能找到现有设置或资料入口。

### 3.3 稍微收拢列表行内间距

知识库和铁路问答继续使用现在的列表形式，标题、搜索、筛选和创建按钮的位置不变。

- 桌面列表行上下内边距现在为 32px，可先试 28px。
- 图标与名称之间的间距只在显得松散时减小 4px 左右。
- 保留知识库名称与描述的层级，不把字号压小来容纳更多行。
- 名称过长时按容器选择换行或截断，截断内容可查看全文。
- 数量、日期和操作菜单保持列对齐；长名称不能挤掉操作菜单。
- 不设置容纳不下长内容的固定行高，不把不同数据强行裁成一样高。
- 手机保留现有精简列策略，单独检查名称与操作按钮的空间。

**验收：** 相同窗口下阅读稍紧凑，长名称仍完整可访问，点击区域依旧宽松。

### 3.4 减少需要反复瞄准的操作

沿用当前图标、胶囊按钮和导航选中线。

- 图标视觉尺寸不必变大；仅当操作难以点中时增加透明点击区域。
- 手机常用图标按钮以约 44px 点击区域为目标；桌面根据空间保留约 36–40px。
- 主题、账户和图标式发送按钮有明确的可访问名称。
- Hover、键盘焦点、禁用和提交中状态都可辨认。
- 提交中继续防止重复提交，不改变已有请求行为。
- 不给所有按钮增加明显跳动或强阴影；现有反馈足够时保留。

**验收：** 鼠标、键盘和手机触控均能操作；增大点击范围不会与邻近按钮重叠。

### 3.5 检查小屏与长文本

保持现有响应式布局与导航测量逻辑，按实际问题做局部修复。

- 顶部导航空间不足时继续使用现有移动菜单，不另设一套导航。
- 场景文字、知识库名、模型名和错误提示不遮住操作按钮。
- 示例问题可以换行，点击后仍填入问题并聚焦，不自动发送。
- 设备分析字段展开后允许页面自然增高。
- 表格或代码块需要滚动时，在局部容器处理。
- 200% 缩放下能找到导航和关键操作，页面不因固定高度裁掉内容。

**验收：** 390px 手机宽度、常用笔记本宽度以及长名称场景下，主要操作可见可用。

## 4. 可选的第二轮：只在对比后确有改善时调整

以下不是必须实施的清单。第一轮完成后，如果现有留白和标题仍然舒服，可以全部保持原值。

| 位置 | 当前桌面值 | 可试的微调值 | 限制 |
| --- | --- | --- | --- |
| 首页主标题 | 88px | 80px | 继续保留大标题，不缩成普通页面标题 |
| 首页标题上下间距 | 36px | 32px | 保留两行品牌表达和原有层级 |
| 首页按钮组上间距 | 36px | 32px | 按钮位置与主次关系不变 |
| 普通列表页标题 | 56px | 52px | 只在与正文比例更协调时采用 |
| 普通列表页标题区留白 | 上 80px / 下 64px | 上 72px / 下 56px | 不压成密集工具条，不影响首页专属规则 |
| 提问章节留白 | 上 100px / 下 120px | 上 88px / 下 104px | 左右分栏、章节标记、内容顺序保持原样 |
| 知识库、问答列表行内留白 | 上下各 32px | 上下各 28px | 不固定行高，尊重实际内容 |

实施时一次只试一组变量，用同样的窗口、主题、内容和滚动位置比较。不要把表中所有值一起套用，也不要同时修改字号、字重、宽度、颜色和圆角。

首页最小视口高度、章节滚动长度、插画位置默认保留。只有真实设备上出现遮挡、裁切等问题时，再针对对应断点修复，不能以“微调”为名删除整段展示。

这些数值来自当前桌面规则。已有 1100px、767px 等媒体查询覆盖必须分别检查，不能把桌面尺寸直接应用到手机。

## 5. 每个页面需要做多少

### 首页

执行第一轮中与提问相关的对齐、状态可读性和小屏检查。保留大标题、引导按钮、章节结构与动效表达，不增加统计卡、快捷入口矩阵或额外右栏。

当前“开始铁路提问”已经调用滚动定位和输入框聚焦；先验证现有行为，不重复实现。

### 知识库列表

优先检查行内间距、长名称、列对齐和操作菜单。现有标题区、筛选、分页、空状态和创建流程保留。

### 铁路问答列表

优先检查图标、名称、进入箭头和操作菜单的对齐。保留当前助手列表的语义，不把它改称“最近会话”，也不改成网格卡片墙。

### 对话页

保持现有会话导航、消息布局和输入区。只有出现阅读过宽、消息与输入框边线不齐、引用难点中等实际问题时，才局部调整。不要预先替换布局或统一重设所有消息宽度。

### 设置与登录页

本轮默认不改。遇到表单字段不齐、错误文本被裁切等明确问题时，只修对应位置。保留现有登录展示区、表单比例和配置分类。

## 6. 配色与视觉细节约束

### 6.1 两套配色完整保留

不修改 `web/tailwind.css` 和 `web/src/styles/levo-theme.css` 中的颜色定义，不新建主题覆盖文件，不改变用户保存的主题选择。

| 用途 | 沿用现有变量或工具类 |
| --- | --- |
| 页面背景 | `var(--bg-base)`、`bg-bg-base` |
| 主文字 | `rgb(var(--text-primary))`、`text-text-primary` |
| 次级文字 | `var(--rail-muted)`、`text-text-secondary` |
| 边框 | `var(--rail-line)`、`border-border-button` |
| 强调色 | `rgb(var(--rail-accent))`、`text-accent-primary` |
| 强调按钮文字 | `var(--rail-on-accent)` |
| 错误信息 | 现有错误语义变量、`--rail-danger` |

`--rail-accent` 是 RGB 通道值，需要 `rgb(...)`；已经是颜色值的变量直接使用 `var(...)`。若某段重要信息过淡，先检查是否误用了禁用文字语义，不直接改全局色值。

### 6.2 保留现有形状与字体

- 沿用当前字体栈和字重表达。
- 保留胶囊主按钮、细边框、轻量链接和现在的图标。
- 不统一改成大圆角卡片，不加玻璃模糊、渐变背景或全页阴影。
- 只对确有不齐的同组控件做对齐，不把全站控件强行设成同一高度。
- 文案的风格与命名默认保留，修正影响理解的内容即可。

### 6.3 保留动效，保证使用连续

知识和档案展示中的线稿动效属于现有表达，继续保留。

检查滚动后内容能否完整呈现、输入与点击是否及时响应，以及系统减少动态效果设置下是否能正常使用。无需另加弹跳、磁吸、视差或按钮追随效果。

## 7. 图片处理

**本轮不需要生成图片。** 保留已有铁路图片和线稿，不为微调新增横幅或更换背景。

后续如果单独希望优化某一张插图，应替换同一位置的资源，保持占位尺寸、构图比例和浅深主题适配。不要因为一张新图重新分配首页空间。

可交给外部生图工具的简短约束：

> 参考提供的现有界面及原插图，只优化这张插图的线条质量与细节。保持原构图、主体位置、宽高比、留白与明暗主题配色；少量沿用现有琥珀色，不新增其他强调色。不要文字、按钮、标志、水印或复杂背景。输出可替换原资源的图像，不重新设计网页。

没有合适素材时继续使用原图，不影响本轮完成。

实施前读取根目录与 `web/AGENTS.md`，以届时实际代码为准：

1. 优先直接修正现有样式规则，不在文件末尾不断追加覆盖层，不增加 `!important` 解决层叠问题。
2. 公共选择器会影响多个页面。先找全部使用位置，必要时用现有页面根类限定范围。

6. 不删除现有插画、章节、导航测量或滚动 hook，不维护另一套“新版首页”。
7. 新增文案遵守现有国际化约定，也检查英文和长文本。
8. 保留当前工作区与任务无关的改动；不顺手处理合并状态或其他业务问题。

## 9. 建议实施顺序

### 第一小批：提问区域

只做内边距对齐、状态文字可读性和长知识库名检查。

交付同一位置的浅色、深色、手机截图，并确认场景切换、示例填入、设备字段和开始对话行为保持正常。

### 第二小批：列表与点击细节

只做必要的行内留白、操作对齐、图标名称和触控范围修正。验证列表操作与顶部导航适配没有变化。

### 最后再决定：是否微调标题和章节间距

用第 4 节的候选值做局部对比。有明确改善才保留；没有改善就维持原值。这一步可以完全不做。

整个过程不包含全局导航迁移、页面重排、重新设计登录页或图片制作。

## 10. 验收标准

### 外观与结构

- [ ] 与原页面对照时，布局、模块顺序、品牌表达和功能位置仍然一致。
- [ ] 浅色与深色两套背景、文字、边框和强调色保持原值。
- [ ] 顶部导航、大标题、章节标记、滚动插画与准备折叠区均保留。
- [ ] 输入正文、设备字段与底部工具区边线更整齐。
- [ ] 列表更容易扫读，同时保留宽松点击区域与必要留白。
- [ ] 没有新增侧栏、右侧状态面板、卡片墙或统计区。

### 使用舒适度

- [ ] 点击“开始铁路提问”能准确定位并聚焦，输入框不会被遮住。
- [ ] 场景选择、示例填入、设备字段、知识库选择及键盘提交行为保持正确。
- [ ] 禁用原因、读取状态、导入进度与错误提示容易读懂。
- [ ] 100 字以上名称、无空格长串、中英文混合内容不会挤掉操作按钮。
- [ ] 1440×900、1366×768、1024px 宽和 390px 手机宽度下操作可达。
- [ ] 手机键盘打开后仍能使用输入与发送；缩放 200% 后没有关键内容被裁掉。
- [ ] 明暗切换、键盘焦点、移动菜单、减少动态效果设置正常。
- [ ] 没有意外的页面横向滚动，局部表格和代码块可按需滚动。

### 验证方式

使用同样的数据、主题、窗口尺寸与滚动位置对比，避免把不同内容造成的差异当成视觉提升。首页介绍区与提问区分别截图，列表至少使用短名称、长名称两组内容。

实施代码时，在 `web/` 下对修改文件执行格式和 lint 检查；涉及 TypeScript 时运行类型检查，完成实际页面修改后做相应构建与浏览器验证：

```bash
npx oxfmt <修改文件>
npx oxfmt --check <修改文件>
npx oxlint <修改文件>
npm run type-check
npm run build
```

尖括号内容需要替换成实际路径。不要为纯间距修改新增镜像式测试；交互行为发生变化时，才补有意义的回归覆盖。

既有检查失败应与新增问题区分。浏览器视觉样例不能代替真实的导入或问答链路验证；本指导书也不代表页面已经完成改造。
