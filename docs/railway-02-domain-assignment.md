## 2. 最短执行顺序

1. 从指导书一选定文献中优先处理GW、GD、YS，消除空库；同时复用CL与XH已有成果。
2. 对结构已经合格的Markdown直接复用；未合格的按指导书三只做必要格式修复和抽样。
3. 用现有已验证的管道导入；按doc_id、内容版本及正式远端文档ID判断是否已存在。相同内容不重复上传、不重新嵌入。
4. 每批成功后记录实际远端ID、所属库及业务切片数；失败文献独立记录并继续其他文献。批量大小按现有服务能力选择，取消固定每批最多5篇和逐批等外部批准的限制，但不要无上限并发压垮本机。
5. 完成18份后进入一次统一验收，不先为每一篇生成一套完整问答审计。

如管道或正文发生实质改变，仅重跑受影响文献。导入任务尚在正常运行时查询任务状态，不提交重复任务。已有合格切片的文档不再经历一轮隔离试切加正式重切。

## 3. 最小登记与真实可用性

复用 `00-control/document-register.json`、`00-control/import-register.md` 或现有导入账本。无需为同一结果再维护多份副本。至少能查到：

`doc_id → 主领域 → 本地Markdown → 正式库ID/文档ID → 解析状态 → 可用业务切片数 → 完整/部分覆盖 → 排除问题`

文献数量达标依赖真实正式入库与内容检查，不能只数本地文件或候选登记。成功上传但解析失败、只导入目录、无业务切片的文献不算完成。

每份至少执行一次真实检索，确认该文献中的一个明确知识点可找回。尽量与指导书三的30题共用请求；同一问题在最终配置下产生的有效结果不重复测。单篇查询失败先排查归档、解析和问题表述，不能仅看远端计数就判定能检索。

## 4. 接入实际演示入口

复用现有可配置的问答/搜索应用，把本轮正式领域库接入用户实际演示入口。优先使用界面或已有接口配置，不另写前后端、不加新路由或新的“智能体系统”。修改前记录原配置以便恢复，保留原库和用户数据。

默认只检索本轮合格文献。若正式库同时有未验收或已知错误内容，利用现有启停/过滤能力将其排除；不要删除原始资料。确认历史库、隔离库、已知废止版本没有被演示入口意外同时检索。

如果现有应用无法一次关联5个库，先核对实际能力，不做临时大改。可以使用现有领域选择功能切换，但必须在交付说明注明；跨领域问题只有真实联合检索可用时才宣称支持，不能用离线脚本成绩冒充前台功能。

## 5. 本阶段不再做什么

- 不逐条审查全部文献的领域标签，不为了跨领域关系新建知识图谱。
- 不要求四份困难细则全部完成；延期文献不阻塞其他领域。
- 不重复检查未变化的全库哈希、旧模型审查缓存和所有历史试切版本。
- 不修改Go/Python迁移路线，不删除Wiki功能或旧代码，不重构后端。
- 不把缺陷隐藏为“已验收”。部分覆盖、延期、失败清楚注明即可。
