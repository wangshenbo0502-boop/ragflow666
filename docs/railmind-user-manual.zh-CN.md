# 轨知 RailMind 详细用户使用说明

适用对象：第一次使用的同学、教师、铁路知识学习者、资料维护人员和本地部署维护人员。

更新日期：2026 年 11 月 15 日。本次补充本机启动、生图、连续改图、语音回答、唱歌和媒体排错；其他章节沿用 11 月 14 日的页面与代码核对记录。

本文按当前“轨知”界面与 Go 处理逻辑编写。功能入口已对照代码核对；实际登录、文档解析、模型回答以及外部平台连接仍取决于你的部署和账号配置。本文的阅读页面检查不代表这些业务已经在你的环境中运行成功。如果页面与本文不同，先确认运行镜像和前端是否来自同一版本。

进阶功能按本次开发代码说明，不同部署版本的入口和字段可能不同；菜单中未出现的功能不要当作已经开放。第 25 章列出了当前未提供普通入口的能力。

阅读版本：[可直接打开的 HTML 手册](railmind-user-manual.zh-CN.html)，支持目录搜索和打印；本文件为完整说明原文。配套文档：[后续升级优化建议书](railmind-upgrade-proposal.zh-CN.md)。

### 0.1 本机快速体验

当前已配置的 Windows 本机环境，在项目根目录打开 PowerShell：

```powershell
.\tools\scripts\start-local-project.ps1
```

启动完成后打开 [轨知工作台](http://localhost/)，用已有账号登录。已有模型、资料和聊天记录可继续使用，不需要重新导入。全新克隆的队友需要先按 README 准备配置和运行资源，不能仅靠这条命令完成首次安装。

| 想先体验什么 | 直接怎么做 |
| --- | --- |
| 资料问答 | 进入“铁路问答”，选择已有助手和会话，输入问题并发送；新建助手按第 5 章操作 |
| 图片生成 | 在已保存的聊天中输入 `@`，选择“生图”，再输入“一列高铁穿过青山，写实摄影”并发送 |
| 连续改图 | 同一会话继续用 `@生图 把上一张改成夕阳，列车保持不变` |
| 语音回答 | 发送 `@语音 用温柔轻松的语气说一句晚安`，完成后播放音频 |
| 唱一小段歌 | 发送 `@语音 唱一段 20 秒的中文晚安歌`，等待本地音乐模型生成 |

生图、语音和唱歌需要相应服务已配置；普通文字聊天成功不代表媒体服务可用。涉及铁路知识的问题，仍按后文检查资料和引用。

本机使用结束后，从项目根目录执行：

```powershell
.\tools\scripts\stop-local-project.ps1
```

该脚本停止项目并关闭配套语音、音乐进程；不会删除业务数据卷。不要把删除数据卷作为日常退出步骤。

## 1. 先弄清楚：这个系统怎么用

你可以把它理解成一个“先翻资料，再回答问题”的铁路知识助手。

你提供资料，系统把资料整理成可以搜索的小段；提问后，它找到相关段落，再让对话模型组织回答。你最后还要检查回答引用的原文。

```text
准备模型 → 导入资料 → 解析完成 → 检索测试 → 选择知识库提问 → 查看引用
```

第一次使用，只需要掌握这一条路线。工作流、知识图谱、数据源、聊天渠道都可以后面再学。

### 1.1 四个最容易混淆的概念

| 界面概念 | 用通俗的话解释 | 例子 |
| --- | --- | --- |
| 模型 | 负责理解、查找或生成文字的能力 | LLM 负责回答，Embedding 负责把资料变成可检索的数据 |
| 知识库 | 一组供助手查询的资料 | “轨知 · 铁路公开规章” |
| 问答助手 | 保存模型、知识库和回答规则的配置 | “轨知 · 安全规章 · …” |
| 会话 | 同一个助手里的一次聊天记录 | “学习安全保护区”“复习实名制规定” |

**创建助手、创建会话、发送消息是三件不同的事。** 首页的“开始对话”会创建助手并进入聊天页；你在首页填写的问题会带入输入框，还需要确认发送。

### 1.2 当前适合做的事

- 根据已入库资料查询铁路规章、客运规则和概念。
- 找到答案对应的文档片段，回看依据。
- 整理课程知识、比较条文、生成待人工核对的学习提纲。
- 在有适用手册时，整理设备现象、相关证据和待确认信息。

当前内置资料没有覆盖具体设备型号的检修手册。系统也没有在铁路问答主路径中接入实时票务或现场设备控制。设备分析结果用于资料查找和分析参考，不能当作现场作业或调度指令。

## 2. 界面导航：该去哪个页面

| 入口 | 你在这里做什么 | 第一次是否需要 |
| --- | --- | --- |
| 工作台 | 选择场景、导入官方资料、查看准备状态、发起铁路问答 | 需要 |
| 知识库 | 上传自己的文件、检查解析、做检索测试、维护资料 | 第二步学习 |
| 铁路问答 | 找到已有助手，继续会话、整理历史记录 | 需要 |
| 更多 | 查看工作流、数据处理流程和编译相关功能 | 暂时跳过 |
| 右上角头像 → 模型设置 | 配置服务商、模型实例和默认模型 | 首次配置需要 |

窗口较窄时，主导航会收进菜单按钮。设置页在窄屏下可能只显示图标；模型配置和复杂表单建议先在电脑宽屏完成。

“知识与模型准备”位于工作台提问区，是可展开的区域。如果看不到“导入官方铁路资料”，先展开它。

## 3. 使用前准备清单

### 3.1 普通使用者需要准备什么

1. 系统访问地址和登录账号。
2. 一个可用的默认对话模型，以及一个可用的默认嵌入模型；管理员已配置时无需重复添加。
3. 想问的问题。如果问设备问题，准备已有的型号、报警记录和适用资料。
4. 第一次练习优先使用内置公开资料，等跑通后再上传复杂 PDF 或扫描件。

页面能打开，只证明前端可以显示。完整问答还需要后端、文档处理服务、存储和模型服务都能正常工作。

### 3.2 访问地址

本仓库配置的常用入口如下，部署人员改过端口时以实际地址为准。

| 场景 | 地址或说明 |
| --- | --- |
| 完整 Docker 部署 | 通常为 [本机 Web 入口](http://localhost/) |
| Vite 前端开发 | 默认 [本机开发入口](http://localhost:9222/)，占用时会自动换端口 |
| Go API | 默认端口 9380，不是日常聊天页面 |
| Admin 服务 | 默认端口 9381，不是普通用户登录入口 |

另一台电脑或手机上的 `localhost` 指向那台设备自己。跨设备访问应使用部署人员提供的地址。

### 3.3 登录或注册

1. 打开系统，进入登录页面。
2. 已有账号时填写邮箱和密码，点击登录。
3. 若页面提供注册入口，可填写邮箱、昵称和密码注册。
4. 若没有注册入口，表示当前配置未开放自助注册，请使用管理员分配的账号。
5. 登录后确认进入“轨知 RailMind”工作台。

新账号可能没有旧账号的模型配置、个人知识库或聊天记录。换账号后列表为空，不代表原数据被删除。

## 4. 配置模型：最先需要做对的一步

### 4.1 为什么要两类模型

| 类型 | 当前页面常见名称 | 作用 | 初次是否需要 |
| --- | --- | --- | --- |
| 对话模型 | LLM | 根据问题和资料生成答案 | 需要 |
| 嵌入模型 | Embedding | 把文档和问题转换成可搜索的向量 | 导入、检索资料需要 |
| 重排序模型 | Rerank | 对候选资料重新排序 | 可以先不配置 |
| 视觉、语音、语音合成等 | 依模型类型显示 | 处理图片或音频等专门任务 | 需要对应任务时再配置 |

一个服务商不一定同时提供对话与嵌入服务。能聊天的模型不能仅靠改个名称就当嵌入模型使用。

### 4.2 操作步骤

1. 在工作台展开“知识与模型准备”，点击“模型设置”；也可以点击右上角头像进入设置。
2. 左侧选择你实际使用的服务商。
3. 没有实例时，右侧会出现待填写的实例卡片；已有实例时，可点击“添加实例”。
4. 填写实例名称，例如 `rail-chat-main`。这是你给连接配置起的名字，不是模型的真实 ID。
5. 按表单填写 API Key、Base URL 或该服务商要求的其他凭据。
6. 在实例的模型区域点击“模型列表”。若服务商不提供模型列表接口，可通过更多菜单选择“添加自定义模型”。
7. 核对模型 ID 和类型，启用需要的模型。手动添加时，使用服务商或本地部署实际提供的模型 ID。
8. 点击实例卡片的保存按钮。没有保存的草稿不能当作配置完成。
9. 如需验证，在模型区域的更多菜单中使用“验证全部模型”，或使用模型行提供的验证操作。验证可能实际调用模型服务。
10. 回到左侧“设置默认模型”，为 `LLM` 和 `Embedding` 分别选择已保存、已启用的对应模型。
11. 默认模型选择会提交保存请求；等待请求成功，再刷新页面确认选择仍然存在。
12. 回到工作台，展开准备区域，确认“对话模型已就绪”和“嵌入模型已就绪”。

“已就绪”在工作台主要表示已取得默认模型 ID，并不等于每次调用都能成功。真实可用性还要通过资料解析和一次问答确认。

### 4.3 当前为什么看不到某个服务商

当前模型侧栏只展示代码允许列表与后端返回列表的交集，允许列表包括 DeepSeek、GLM / 智谱、自定义 / OpenAI 兼容、讯飞 / Spark、阿里云 / 通义千问、小米 / MiMo。其他服务商即使在底层配置中存在，也不一定有当前页面入口。

若服务确实支持对应的 OpenAI 兼容协议，可以使用“自定义 / OpenAI 兼容”。这不代表所有服务都能通过这个入口接入；需要核对它提供的接口和模型类型。

### 4.4 字段怎样填才不容易出错

| 字段 | 应填写的内容 | 常见误填 |
| --- | --- | --- |
| 实例名称 | 自己取的易识别名称 | 把密钥填在这里 |
| API Key | 当前服务商签发的访问密钥 | 复制了其他服务商的密钥，或只复制到一部分 |
| Base URL | 服务商说明中的 API 基地址 | 填成网站首页，或者随意追加完整聊天接口路径 |
| 模型 ID | API 实际支持的标识 | 填成宣传名称或实例名称 |
| 模型类型 | Chat、Embedding、Rerank 等真实能力 | 把 Chat 误设成 Embedding |

本说明不固定推荐某个商业模型和价格。先使用你已有权限的服务，确认对话、嵌入各一项可用，再做质量比较。

如果 Go 后端运行在 Docker 内，本地模型服务运行在 Windows 宿主机，容器里的 `localhost` 通常不是 Windows 宿主机。当前 Compose 已配置 `host.docker.internal`，部署人员可据此核对连接地址、监听地址和防火墙。

## 5. 第一次完整操作：用内置资料完成一次问答

这一节的目标是得到一条可以回看依据的回答，不需要预先研究全部设置。

### 步骤一：导入资料

1. 回到“工作台”。
2. 展开“知识与模型准备”。
3. 确认嵌入模型已配置；否则导入按钮不可用。
4. 点击“导入官方铁路资料”。
5. 观察“准备个人铁路知识库”“正在上传”等进度提示。

系统会创建或复用当前用户拥有的“轨知 · 铁路公开规章”知识库，并上传项目自带的资料文件、提交解析任务。这里的“导入”读取本项目打包的存档，不是点击后实时去官方网站下载最新规章。

### 步骤二：等待解析

展开“查看资料解析状态”。不要只看“已上传”就开始判断问答效果。

| 状态 | 含义 | 你要做什么 |
| --- | --- | --- |
| 待解析 | 文件已存在，但尚未处理 | 对内置资料可重试导入；自有文件可在文件列表执行解析 |
| 已排队 | 解析任务已提交，等待处理 | 等待；长时间不动时让维护人员检查任务服务 |
| 解析中 | 正在处理文档 | 等待，不要连续重复提交 |
| 已完成 | 本次解析流程结束 | 还要确认存在片段，再做检索测试 |
| 解析失败 | 任务遇到错误 | 读取失败信息，修正原因后重试 |
| 已取消 / 正在停止 | 任务被取消或正在停止 | 等停止完成后决定是否重新解析 |

当前工作台的开始条件是：默认对话模型存在、已选择知识库、知识库有片段，并且至少一份文档处于完成状态且片段数大于 0。一次完整演示建议等计划使用的资料全部完成，避免只在部分资料里检索。

### 步骤三：选择场景和资料范围

1. 选择“安全规章”。
2. 在“资料范围”下拉框中确认选中“轨知 · 铁路公开规章”。
3. 输入下面的问题，或点击当前场景显示的“试着问”。

```text
请根据知识库解释铁路线路安全保护区的概念，并标出依据。
如果资料存在适用条件，请分别说明；不要推断未提供的现场情况。
```

工作台可能自动选中一个已有知识库，因此每次换场景都应看一眼资料范围。选择场景不会自动帮你补齐该场景需要的专业资料。

### 步骤四：进入聊天并确认发送

1. 点击“开始对话”。工作台支持 `Ctrl + Enter`；Mac 可用 `Command + Enter`。
2. 系统创建助手并进入聊天页。
3. 检查输入框中已带入的问题。
4. 点击聊天页的发送按钮，等待回答。

**进入聊天页后没有立即出现回答，先检查问题是否还在输入框。当前首页流程只带入问题，不自动发送。**

### 步骤五：检查依据

1. 阅读回答中的引用标记和参考资料。
2. 点击引用关联的文档或片段，打开资料查看区域。
3. 核对原文是否支持回答的关键结论。
4. 注意适用范围、资料名称和版本说明。Markdown 存档不一定有原始 PDF 页码，不要求每种文件都能精确跳页。
5. 如果只是文档主题相近，原文没有支持具体结论，这条回答仍应标记为需要复核。

### 第一次使用的完成标准

- 能登录。
- 默认对话模型和嵌入模型均已配置。
- 至少一份文档解析完成且有片段。
- 能发出问题并收到响应。
- 能打开相关来源，判断回答是否有依据。

满足这些条件，才算跑通最小使用流程。回答流畅、界面显示正常，都不能单独证明检索和引用正确。

## 6. 内置的六份资料是什么

| 资料名称 | 适合先尝试的问题方向 |
| --- | --- |
| 铁路安全管理条例 | 铁路安全责任、安全保护区等概念 |
| 铁路交通事故应急救援和调查处理条例 | 救援职责与调查职责的区别 |
| 铁路旅客运输规程 | 旅客运输合同和一般规则 |
| 铁路旅客运输安全检查管理办法 | 安检中的责任、权利与义务 |
| 铁路旅客车票实名制管理办法 | 实名制规则及适用条件 |
| 铁路设备质量安全监督管理办法 | 设备质量监督、报告和追溯 |

本地清单记录的发布网站为国家铁路局，采集日期为 2026 年 10 月 12 日。工作台“官方资料”区域可以查看原始来源链接和采集日期。采集日期表示存档时间，不表示生效日期或今天仍然适用的证明。

重新点击导入会按文件名跳过已有文件，并对未开始、失败或已停止的相关任务尝试提交解析；不会自动替换同名文件中的旧正文。已经更新了本地资料包时，应由资料维护人员核对版本后更新库内文件，再重新解析。

## 7. 上传你自己的资料

### 7.1 先决定怎样分库

初期可以按用途建立少量知识库：

| 建议库名 | 内容 |
| --- | --- |
| 铁路公开规章 | 经核对的公开规章资料 |
| 某课程教学资料 | 讲义、术语、练习材料 |
| 某设备型号技术资料 | 该型号的适用说明书、报警说明、维修资料 |
| 脱敏故障案例 | 经授权、去除不必要个人信息的案例记录 |

这些名称是组织建议，不是系统自动生成的固定模块。初期不把多个不同型号、不同版本的手册全部混进同一个库。

### 7.2 创建知识库

1. 点击主导航“知识库”。
2. 点击“创建知识库”。
3. 填写一个能说明主题的名称。
4. 选择已启用的 Embedding 模型。
5. 选择内置解析方式。初次用普通文字、Markdown 或结构清楚的文档时，可先用“通用”；复杂表格、图片或手册再按文件特点选择。
6. 保存并进入知识库。

初次不必创建自定义数据处理流程。后续只在实际解析结果不满足需求时调整。

### 7.3 上传与解析

1. 在知识库左侧选择“文件列表”。
2. 点击添加文件按钮，在菜单中选择“上传文件”。
3. 选择文件。
4. 若希望上传后立即处理，打开“创建时解析”。**当前上传弹窗默认关闭这个选项。**
5. 提交上传，回到文件列表。
6. 如果未启用自动解析，勾选文件，使用“解析”操作。
7. 等待完成，检查片段数和日志。

文件格式能否处理，还取决于所选解析方式及对应模型是否已配置。页面提示缺少解析能力或模型时，先补齐配置，再运行；不要把“上传成功”理解为所有文件都已成功进入检索。

第一次建议先上传一份结构清楚的小文档。它成功后，再分批导入扫描件、复杂表格和大文件，便于定位问题。

### 7.4 怎样检查解析结果

进入文件对应的片段或解析结果页面，至少抽查以下内容：

- 标题与正文有没有混在一起。
- 条款编号、否定词、数字和单位有没有错。
- 表格中的设备名称、参数和值是否仍能对应。
- 跨页内容有没有断裂或重复。
- OCR 文本是否出现明显乱码。
- 文件显示完成，但片段是否为 0。

若原始资料就缺页或无法辨认，换模型通常不能恢复缺失内容。先修正资料来源和质量。

### 7.5 修改解析设置后要注意什么

知识库左侧的分块设置页面用于配置解析方式及相关参数。当前页面支持保存设置，并在适用时提示是否应用到已有文档。

保存配置、把配置应用到已有文档、重新解析，是需要分别检查的环节。完成调整后应确认相关文档重新处理成功，再做检索测试；不要假设保存设置会立即重算所有旧片段。

已有片段时，当前界面的 Embedding 选择会被禁用。如果要换嵌入模型，建议建立新知识库、重新上传和解析原始资料，验证后再切换助手绑定。不要为了切换模型直接清空唯一的数据副本。

### 7.6 怎样维护版本

建议文件名包含主题、型号和版本，例如 `设备A_报警说明_教学版_2026-11.md`；正文开头保留来源、适用范围和版本信息。能使用文档元数据时，也把这些信息写入元数据。

本项目有通用元数据和过滤能力，但没有因此自动完成“规章有效性审查”。正式使用哪些版本，仍需要资料负责人确认。

## 8. 检索测试：答不对时先查这一页

检索测试只检查“有没有找到合适的资料片段”，不要把它与完整问答混为一谈。上游官方入门流程也先做检索测试再创建问答，但本项目按钮与布局以本地界面为准。[RAGFlow 官方入门说明](https://ragflow.io/docs)

### 8.1 操作步骤

1. 打开目标知识库。
2. 选择左侧“检索测试”。
3. 先输入一条你确认能在原文找到答案的问题。
4. 保持默认检索参数，点击“运行”。
5. 查看返回片段及其来源文档。
6. 对照原文，记录是否命中真正支持答案的内容。

### 8.2 怎样理解结果

| 结果 | 优先检查 |
| --- | --- |
| 没有片段 | 文档是否完成、是否启用、是否有片段、资料是否真的包含答案、过滤条件是否过严 |
| 有片段，但主题不对 | 问题表述、知识库选择、资料质量、切分质量、检索参数 |
| 有正确片段，但聊天仍答错 | 助手绑定、对话模型、提示配置、上下文和引用组织 |
| 原文正确，但片段数字错 | OCR、表格解析或切分结果 |
| 同一问题命中多个版本 | 资料版本和适用范围整理、过滤条件 |

### 8.3 参数用最少的方式理解

| 参数 | 含义 | 初学者怎么做 |
| --- | --- | --- |
| 相似度阈值 | 控制哪些候选片段能够进入结果 | 先不改；漏检时小幅调整并重复同一组题目 |
| 关键词相似度权重 | 控制字面匹配与向量匹配的组合 | 报警代码、型号类问题注意精确词是否命中 |
| 返回数量 / Top N | 取多少片段供显示或回答使用 | 保持默认起步；越大不一定越准 |
| 重排序候选数量 | 送去重新排序的候选范围 | 与返回数量配合使用；数量增大可能增加耗时 |
| Rerank | 进一步排列相关资料 | 先确认普通检索有效，再比较它的实际收益 |
| 元数据过滤 | 按文档属性限定范围 | 属性确实存在且值正确时再使用 |

相似度分数不是“答案正确概率”。每次只改一个参数，用固定问题比较结果，不能因为一题变好就断定所有问题都改善。

## 9. 四种场景怎样提问

### 9.1 安全规章

适合查规定、概念和职责。尽量说明想了解哪类对象、哪份资料，不要求系统代替现场判断。

```text
请根据当前知识库，整理“铁路安全隐患报告责任”的相关规定。
按“责任主体、资料支持的要求、依据、仍需核对的适用条件”回答。
没有找到依据的内容请直接说明。
```

### 9.2 客运服务

适合查资料中的一般规则。实时余票、价格、当日时刻、退改签办理结果，需要在实际业务渠道核对。

```text
请根据已导入的旅客运输和实名制资料，解释儿童乘车的相关实名制要求。
列明原文依据和适用条件，并说明本次回答未查询实时票务信息。
```

### 9.3 设备分析

选择“设备分析”后，工作台会出现以下字段：

| 字段 | 怎样填写 |
| --- | --- |
| 设备型号 | 按已有铭牌记录或文件填写，不知道就留空 |
| 报警代码或提示 | 尽量抄录原始文字，保留字母、数字和大小写 |
| 发生位置 | 填已有记录中的位置，可使用教学或脱敏标识 |
| 发生时间 | 按使用者当地时间填写 |

这些字段会组装进待发送的问题，并非创建独立设备台账或维修工单。

```text
这是教学案例。某设备出现间歇性报警，具体记录见上面的背景字段。
请只依据所选知识库整理：已知现象、资料支持的可能原因、
尚不能确认的判断、还需要补充的信息，并给出引用。
如果没有适用型号的手册，请说明无法判断，不编造参数。
```

如果选的仍是公开规章库，它通常无法回答具体设备复位参数和检修细节。此时提示资料不足是合理结果，下一步是补充适用资料。

### 9.4 学习培训

```text
请根据知识库做一份“铁路事故应急救援与事故调查职责”的学习提纲。
分成概念、职责对比、易混点和三个自测问题。
自测题的参考答案请附资料依据，假设案例要明确标注。
```

当前是通过问答帮助学习。独立的考试、成绩统计、错题本和班级管理不应当作已经交付的功能。

## 10. 管理助手和聊天记录

### 10.1 继续使用已有助手

1. 点击“铁路问答”。
2. 在助手列表里找到之前由工作台创建的助手。
3. 点击卡片进入。
4. 在左侧选择旧会话继续提问，或通过加号创建新会话。

手机上的会话列表由会话按钮打开。讨论不同案例时建议新建会话，避免上下文互相影响。

### 10.2 不要每次都创建一个新助手

当前工作台每点一次“开始对话”都会创建一个新助手，名称包含场景和随机标识。如果模型、资料范围和用途没变化，日常使用可以进入已有助手，再创建会话。

助手卡片的更多菜单可以用于重命名等管理操作。可以命名为“安全规章学习助手”或“设备A教学助手”，便于以后找到。

### 10.3 从列表新建铁路问答

“铁路问答”列表页顶部和空列表中的“新建铁路问答”都进入工作台，并将焦点移到问题输入框。浏览器返回按钮可以回到列表。

1. 选择安全规章、客运服务、设备分析或学习培训场景。
2. 核对默认对话模型和知识库，确保至少有一份已完成解析且有可检索片段的资料。
3. 填写问题；设备分析场景可补充设备背景。
4. 点击“开始对话”创建助手，进入聊天页核对预填内容后再发送。创建不会自动发送问题。

创建失败时，工作台会保留场景、资料范围和已填写内容，修复问题后可以重试。服务端也会检查场景、模型和资料状态，避免页面显示就绪后资料状态变化仍创建无资料的铁路助手。

助手卡片根据保存的领域和场景显示分类。单纯给通用助手起一个铁路名称，不会启用铁路领域规则；已有通用助手仍显示为“知识问答”。

### 10.4 修改助手配置

1. 进入助手，点击聊天区域右侧的齿轮按钮。
2. 在“聊天设置”中核对名称、对话模型、知识库。
3. 按需要修改，并点击底部保存。
4. 建立新会话，用同一个测试问题验证效果。

当前通用设置界面仍可能显示提示词、引用、联网等选项。但对带铁路标记的助手，Go 请求处理会固定铁路系统提示、引用和无依据回复，并关闭该路径的联网选项。界面允许修改，并不代表这些修改会改变铁路模式的实际行为。

初学者先只管理名称、模型和知识库；检索参数通过固定问题逐项比较。研究模式及复杂配置应在完成基础流程后，由维护人员针对实际后端路径验证。

### 10.5 反馈与删除

回答操作区提供反馈等操作。反馈时最好写清楚“哪句话、哪份资料、为什么有问题”，例如：

```text
问题：……
需要复核的回答原句：……
引用的文档与片段：……
原文实际内容：……
问题类型：资料缺失 / 检索错误 / 引用不支持 / 回答越界 / 其他
```

点不满意不会自动训练模型或修正知识库。资料维护人员仍需定位原因、修改资料或配置并重新验证。

删除会话或助手前，确认没有需要保留的学习记录。不要把删除当成解决模型调用失败或解析失败的第一步。

## 11. 进阶功能总览与阅读路线

| 功能 | 适用情况 | 先完成什么 |
| --- | --- | --- |
| 知识成果 | 查看处理流程生成的 Wiki、结构图等整理结果，详见第 19 章 | 文档解析和基础检索有效；相关生成配置可用 |
| 数据处理流程 | 文件类型复杂，需要定制解析与处理步骤 | 先证明默认解析不能满足目标 |
| 工作流 | 任务需要多步处理、条件分支或工具组合 | 基础问答已稳定；工具权限和输出经过验证 |
| 编译相关配置 | 定制知识整理产物 | 理解输入资料和预期成果，并检查额外模型调用 |
| 数据源 | 周期性同步外部资料 | 先通过手动上传验证资料质量和检索效果 |
| 聊天渠道 | 从外部渠道访问助手 | 先完成浏览器内测试和访问控制验证 |

知识成果不是上传后必然已有的内容；它由配置了知识编译器的处理流程生成，查看成果页不会开始生成。详细步骤和子选项见第 19～24 章。当前侧栏、路由和开源能力与通用 RAGFlow 教程并不完全相同，找不到团队、MCP、API 或独立搜索入口时，可先查第 25 章确认当前入口范围。

## 12. 常见问题与排查顺序

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 网页打不开 | 地址、实际端口、前端和 Docker 是否启动 | 由部署人员检查服务状态 |
| 网页能打开但登录失败 | 账号密码、注册是否开放、API 是否可达 | 查看登录请求错误，不要只重启浏览器 |
| 导入按钮灰色 | 默认 Embedding 是否已选择 | 到模型设置完成配置 |
| “开始对话”灰色 | 默认 LLM、知识库选择、完成状态、片段数 | 展开“知识与模型准备”逐项检查 |
| 导入提示完整性校验失败 | 当前静态文件是否与资料清单匹配 | 由维护人员重新核对文件和 SHA-256，不绕过校验 |
| “当前环境不支持资料完整性校验” | 当前地址是否支持浏览器安全上下文 | 非本机 HTTP 访问可请部署人员配置 HTTPS |
| 文件上传了却一直待解析 | 是否开启“创建时解析” | 在文件列表执行解析 |
| 一直排队 | ingestor、NATS、任务状态和服务日志 | 让维护人员定位；不要连续重复导入 |
| 解析失败 | 文档日志、嵌入模型、解析模型、存储或索引错误 | 针对错误修正后重试 |
| 已完成但片段数为 0 | 空文件、提取结果、解析方式 | 抽查原文与解析产物 |
| 提示资料不足 | 所选库是否真的含答案 | 先做检索测试，缺资料就补资料 |
| 配置了模型却无法选择 | 模型是否保存、启用、类型正确 | 返回实例模型列表确认 |
| 模型报 401 / 403 | 密钥、权限和服务商设置 | 由配置人员核对凭据；不要在反馈里粘贴密钥 |
| 模型报 429 / 超时 | 服务商限额、并发、网络、输入长度 | 稍后重试并查看服务端错误 |
| 首页进入聊天后没回答 | 问题是否还在输入框 | 确认内容并点击发送 |
| 改了系统提示词却没生效 | 是否为铁路专用助手 | 该模式的部分规则由后端固定 |
| 引用了资料但答案仍不对 | 引用是否逐项支持结论 | 记录错误并检查检索和生成环节 |
| 换了模型，旧库表现异常 | 改的是聊天模型还是嵌入模型 | 嵌入模型变更要重新建立一致的索引 |
| 修改源码后页面没变 | 浏览器访问的是 Vite 还是旧镜像 | 部署正确版本后再检查缓存 |
| 教程说有某个菜单但没有 | 教程与当前定制版本是否一致 | 按本文导航表确认当前入口 |

建议按这个顺序排查，避免一次改很多设置：

```text
能否访问服务？
  → 模型是否可调用？
  → 文档是否解析完成并有片段？
  → 检索测试能否找到正确原文？
  → 助手是否绑定该知识库？
  → 模型回答是否正确使用证据？
```

## 13. 给部署维护人员的简明附录

以下是当前仓库配置的核对方式，不是本次已成功运行的记录。普通使用者可以跳过。

### 13.1 启动前核对

- Docker Desktop 已启动，且当前使用 Linux 容器引擎。
- `docker/.env` 中的镜像、端口和依赖配置符合当前环境。
- Compose 引用了 `.env.local`，确认该文件由部署人员正确准备。
- 当前配置中的主镜像名为 `ragflow:railmind-v1.0.0`，这是本地定制标签，不保证公共仓库存在。镜像缺失时应先取得或构建与代码对应的镜像。

### 13.2 常用命令

当前已配置的 Windows 本机应使用配套启动脚本，以同时管理语音和音乐服务。在项目根目录执行：

```powershell
.\tools\scripts\start-local-project.ps1
```

仅检查 Docker 状态时，在项目根目录执行：

```powershell
docker version
docker compose --env-file docker/.env -f docker/docker-compose.yml config --services
docker compose --env-file docker/.env -f docker/docker-compose.yml ps
```

开发前端时，在另一个终端执行；依赖已正确安装时可直接运行开发命令：

```powershell
Set-Location D:\ragflow\web
npm ci
npm run dev
```

Vite 默认把 `/api`、`/v1` 转到本机 9380，把 `/api/v1/admin` 转到 9381。如果修改后端端口，代理目标也要保持一致。以终端实际显示的前端地址为准。

API 只读探测示例：

```powershell
Invoke-RestMethod http://localhost/api/v1/system/healthz
Invoke-RestMethod http://127.0.0.1:18880/health
Invoke-RestMethod http://127.0.0.1:18881/health
```

后两个地址分别检查本机语音和音乐服务。关闭本机项目使用 `.\tools\scripts\stop-local-project.ps1`。完整准备条件见 [本地启动说明](ai-local-startup-guide.md) 和 [本地媒体说明](chat-media-local.md)；排错时不要把含有真实密钥的配置或完整日志发到公开仓库。

健康接口通过后，还应实际验证上传、解析、检索和问答。服务能响应不代表整条链路可用。

### 13.3 数据保存与维护

停止服务时使用保留数据的操作，不把删除数据卷当作常规排错步骤。备份至少覆盖业务数据库、原始文件、检索索引或可重建材料、模型与应用配置；恢复时要验证它们属于同一个一致的版本。

Docker 数据卷独立于容器生命周期，镜像也不等于数据库备份。备份要做恢复演练，不能只检查压缩包是否生成。[Docker 数据卷文档](https://docs.docker.com/engine/storage/volumes/)

Go 修改的测试和构建统一遵循仓库 `build.sh` 与 AGENTS 指引；不要因缺少原生库而切回 Python 服务。部署入口与历史验证见[铁路智能体说明](railway-agent.md)，其中镜像名、路径和环境假设须与当前配置核对。

## 16. 工作台：每个区域是干什么的

### 16.1 场景选择：改变这次问题的背景

**用途：** 告诉助手你正在做哪类任务，帮助组织提问和回答要求。场景不等于四套独立模型，也不会自动补全缺失的专业资料。

| 子功能 | 什么时候选 | 可以这样问 | 看什么结果 |
| --- | --- | --- | --- |
| 安全规章 | 查询规定、责任、概念、适用条件 | “按责任主体整理隐患报告要求，附依据” | 引用是否来自有关规章，条件是否完整 |
| 客运服务 | 学习乘车、安检、实名制等资料内容 | “对比实名制与安全检查的要求” | 不把一般规定说成实时办理结果 |
| 设备分析 | 已有现象记录和适用设备资料，需要查找依据 | “只按 A1 教学手册整理报警的已知信息和待查项” | 是否匹配型号；无手册时明确说明不足 |
| 学习培训 | 做提纲、概念对比、案例讨论、自测题 | “生成三道练习题并附参考依据” | 题目和答案可回查；假设案例有标记 |

**操作：** 选择场景 → 选择资料范围 → 填写具体问题 → 检查准备状态 → 开始对话 → 在聊天页发送。详细提问模板见第 9 章。

### 16.2 知识与模型准备：查看能不能开始

这个可展开区域把“回答能力”和“资料准备”放在一起检查。收起时只是隐藏内容，并没有停止后台解析。

| 子功能或状态 | 含义 | 你该做什么 |
| --- | --- | --- |
| 模型设置 | 打开服务商、模型实例及默认模型配置 | 按第 4 章准备默认对话模型和 Embedding |
| 导入官方铁路资料 | 导入项目附带的六份公开资料存档 | 点击后去知识库检查解析；不是现场联网抓取最新版本 |
| 知识库选择 | 限定这次助手能查询的资料范围 | 选与问题匹配的库，不是库越多越好 |
| 已完成资料、片段数 | 提示是否已有可用资料 | 至少一份已完成且片段数大于 0；仅上传不算完成 |
| 模型就绪提示 | 已保存必要的模型选择 | 仍需实际调用验证密钥、额度、网络和模型支持情况 |

重复导入会复用对应个人知识库，并按文件名跳过已有文件、处理可重试的解析状态。它不是“覆盖成最新版”的更新按钮。更换资料版本应由维护人员核对后管理。

### 16.3 提问区、设备背景和开始对话

问题输入框写“要解决的事”，例如“请解释 A1 教学手册中 E01 的定义，找不到就说明”。设备型号、报警、位置、时间写已知背景，未知内容不必猜。

**“开始对话”保存的是一个新助手。** 首页填写的问题会带入聊天输入框；检查内容后还要发送。想继续上次讨论时，从“铁路问答”进入原助手即可，避免积累大量相同助手。

开始按钮不可用时，先展开准备区；开始失败时，优先按提示检查模型、知识库和解析状态。反复点击不会让资料更快处理。

### 16.4 工作台不能代替哪些系统

工作台负责发起知识问答。设备背景不是设备资产台账；学习培训不是考试成绩系统；客运问答不是购票页面。需要具体业务记录或现场操作时，应回到对应业务系统。

## 17. 知识库：从文件到可用资料的全部环节

### 17.1 知识库列表、新建和搜索

**用途：** 按资料用途分组，控制助手查哪些内容。进入顶部“知识库”，搜索已有库；新建时起一个能说明主题和版本范围的名称，例如“设备 A1 教学资料”。

列表中的文件数表示已保存多少文档；片段数表示处理后得到多少检索单元；更新时间用于判断近期是否有变动。数量多不说明内容准确。进入库后，左侧依次使用文件列表、检索测试、日志、分块设置、知识成果。

重命名只改变识别名称；删除知识库属于移除资料容器的操作，应先确认需要保留的原文件。删除不是修复模型故障的方法。

### 17.2 添加文件：上传文件与空文件

| 子功能 | 作用 | 操作方法 | 完成标志 |
| --- | --- | --- | --- |
| 上传文件 | 保存你电脑上的资料 | 添加文件 → 上传文件 → 选择文件 → 确认 | 文件出现在列表 |
| 创建时解析 | 上传后接着执行文档处理 | 上传弹窗中主动开启；当前默认关闭 | 状态进入排队或处理中 |
| 空文件 | 创建没有上传原件的虚拟文档，用来手工维护片段 | 添加文件 → 空文件 → 命名，再进入片段页添加内容 | 有文档条目，手工添加后有片段 |

**上传成功与解析成功是两次检查。** 新手先上传一份短 Markdown 或文字清晰的文档，再处理复杂扫描 PDF。空文件没有原始附件可下载，也不按普通文件批量解析。

示例：创建“教学问答补充”空文件，添加一条经审核的概念解释，并在片段正文写清来源。它适合人工维护少量知识，不会自动验证你输入的内容。

### 17.3 文件列表每列和每个图标

| 列、图标或操作 | 含义与使用方法 |
| --- | --- |
| 文件名 | 点击进入该文档的真实片段页面，核对处理后的内容 |
| 上传时间、排序箭头 | 判断先后顺序；点击列头箭头改变排序 |
| 片段数量 | 文档处理后的检索单元数；完成但为 0 时仍要排查 |
| 启用开关 | 控制文档是否参与后续检索；关掉通常用于暂时停用 |
| 解析状态和解析菜单 | 开始处理、查看状态或选择可用处理配置 |
| 日志入口 | 查看这份文档处理过程中的信息与失败原因 |
| 铅笔 | 重命名；不会把文件正文替换成新内容 |
| 眼睛 | 查看或管理文件元数据，不是打开全文原件 |
| 下载 | 取回可下载的原始文件；空文件不提供原件 |
| 垃圾桶 | 删除文档，按确认弹窗核对对象 |

部分行操作在鼠标移入或键盘焦点进入后才出现。处理中的文件会限制重命名、下载、删除等操作，先等待完成或按需要取消任务。

### 17.4 批量选择、解析、取消、启用、禁用与删除

先勾选文件行，再使用批量菜单。表头勾选以当前页面显示的行范围为准，翻页后重新核对选择。

1. **解析：** 为有效文件创建处理任务。混合选择中，虚拟文档、不支持类型或缺少必要模型的文件可能被跳过，阅读提示并核对实际入队数量。
2. **取消：** 请求停止尚未完成的处理。取消不等于删除原件，也不代表已有片段已清除。
3. **启用 / 禁用：** 决定这些资料是否参与后续检索。暂时停用旧版本可先禁用。
4. **元数据：** 给选中文档维护共同属性，确认是否应对所有选中文件使用同一值。
5. **删除：** 移除选中资料。确认名称和数量，避免把整页选择误当成一个文件。

重新解析可能清理或重建已有片段，包括手工修订内容。看到确认弹窗时先读清处理范围；需要长期保留的修订，应同时更新源文档。

### 17.5 状态到底表示什么

| 状态 | 当前发生什么 | 下一步 |
| --- | --- | --- |
| 待解析 | 原件已保存，尚未开始处理 | 选择解析 |
| 排队 | 任务已提交，等待处理服务 | 稍后查看；长时间不动请维护人员检查任务服务 |
| 处理中 | 正在读取、切分、提取或建立索引 | 等待，查看日志了解具体阶段 |
| 完成 | 处理任务结束 | 核对片段数、内容及检索命中 |
| 失败 | 某一步执行异常 | 看日志中的首个有效错误，修复后重试 |
| 已取消 | 处理被停止 | 根据需要重新解析 |

状态完成不是内容质量证明。扫描件的数字、表格列、单位、条款编号仍需人工抽查。

### 17.6 片段页面：查看、搜索和对照原文

**入口：** 文件列表 → 点击文件名。此处的片段是后续检索的重要材料。

| 子功能 | 怎样使用 | 对系统内容的影响 |
| --- | --- | --- |
| 全文 / 省略显示 | 切换片段展开程度，便于精读或快速浏览 | 仅改变显示 |
| 片段搜索 | 输入原文关键字，例如 `E01` | 缩小当前文档的片段列表 |
| 启用状态筛选 | 筛选全部、启用或禁用片段 | 仅改变显示范围 |
| 分页 | 查看其他片段；换页后重新确认选择 | 仅改变显示范围 |
| 文档视图与原文定位 | 有可用原件、页码及位置时对照高亮 | 不保证所有文件都能逐页定位 |
| 点击片段或结构节点 | 查看关联证据、声明或对应片段 | 关联内容必须已由处理流程生成 |

文档区域的“预览 / Preview”看原始文件；“Artifact”看知识编译后生成的结构。Artifact 中先选可用的成果类型，再搜索实体或点击节点，右侧会筛出关联片段；树形成果有对应数据时还能查看声明与证据。切回预览会清除结构节点带来的片段筛选。这里空白不一定是上传失败，也可能只是该文档还没有运行知识编译，生成方法见第 19.2 节。

先确认文件名和片段内容属于你的资料。若从旧链接进入看到 `xxx`、重复几何示例或无响应的 Save / Copy / Export，那是尚未完成接入的预览页面；不要把示例当成已解析的资料，也不要依赖这些按钮保存。返回知识库，从文件名进入当前片段页。

### 17.7 片段编辑、新增、启用与批量维护

**编辑：** 在真实片段页面双击片段正文，打开编辑框；修改后确认，再搜索刚修改的关键字核对。**新增：** 点加号，填写正文，并检查“启用”是否打开。新增框中的开关不能跳过，否则片段可能保存成禁用状态。

| 编辑子项 | 是什么 | 示例或用法 |
| --- | --- | --- |
| 正文 | 供检索与回答引用的内容 | 写完整定义及适用范围，不只填一个标题 |
| 关键词 | 帮助表达重要字面词 | `E01`、`报警`，应与正文有关 |
| 问题 | 该片段可回答的问题表达 | “E01 在 A1 教学手册中是什么意思？” |
| 标签 | 对片段进行标记 | `教学资料`；不是自动授予访问权限 |
| 图片 | 在对应编辑能力可用时补充片段图像 | 确认图片与正文相符 |
| 标签特征 | 标签解析场景中的结构化特征 | 只在你明确使用该解析方式时维护 |
| 启用 | 让片段参与后续检索 | 保存后重新做检索测试 |

片段卡片上的开关可单独启用或禁用。勾选片段后，可批量启用、禁用或删除；全选作用于当前加载页面。禁用比删除更适合临时排查坏片段。手工改片段不会同步改写原始附件，重新解析时应再次核对。

### 17.8 元数据：给资料贴可筛选的属性

**用途：** 在不同型号、版本、来源之间限制检索范围。元数据是字段和值，例如 `device_model = A1`、`version = 2026-11`，不同于正文里随意写的备注。

**操作示例：**

1. 在文件行眼睛图标或批量元数据入口打开管理框。
2. 创建或选择字段 `device_model`，按字段要求设置类型，填写 `A1`。
3. 给对应文档保存；其他型号填写各自的值。
4. 进入检索测试，添加该字段的过滤条件，选择匹配 `A1`。
5. 运行同一个问题，确认来源只剩符合条件的资料。

字段名、大小写、字段类型、值都要一致。设置过滤却没有给文档填写属性，容易把本来能找到的资料排除。元数据不会自动审查规章时效，也不自动把所有文档识别成正确型号。

### 17.9 分块设置：保存处理规则

**用途：** 决定这个库的文档如何读取、切分和建立索引。先理解“分块”是把长文整理成便于查找的内容单元。

| 设置类别 | 作用 | 如何使用 |
| --- | --- | --- |
| 名称、图标、描述 | 帮助识别知识库用途 | 描述写主题、来源、版本范围 |
| Embedding 模型 | 把资料转为向量供语义检索 | 优先在导入前确定；有片段时选择会受限制 |
| 解析模式 / 内置流程 | 使用已有的文档处理规则 | 初学者选与资料类型匹配的现成流程 |
| 自定义数据处理流程 | 使用自己发布的处理步骤 | 按第 21 章建立并发布后再绑定 |
| 节点参数 | 调整解析、切分、提取和索引 | 每次改一项，用小样本文档验证 |
| 文档重要性 / PageRank 类参数 | 在检索相关性之外影响资料权重 | 按实际可见项设置；不能用高权重修复错误资料 |
| 关联数据源 | 将已配置来源接入该知识库 | 见第 23.2 节，还需确定自动解析 |

**生效顺序：** 保存设置 → 确认对已有文档应用的配置 → 对需要更新的文档重新解析 → 检查片段 → 做检索测试。保存不代表历史索引瞬间全部更新。

### 17.10 日志：判断卡在哪一步

知识库 → 日志，可按页面提供的文件处理、数据源处理等分类查看任务。查看状态、时间、对应对象，点详情或眼睛查看实际消息。

例如：上传已成功，但日志提示嵌入模型调用失败，应该检查 Embedding 的地址、密钥、额度和输出维度；不用反复重新上传。看到解析成功但零片段，应检查文件是否可读、页码范围和切分配置。

任务数量和成功率表示处理任务情况，不等于问答准确率。向维护人员反馈时提供文档名、处理时间、失败阶段和错误摘要；凭据字段不要当成问题描述发送。

### 17.11 检索测试的进阶子功能

基础步骤见第 8 章。调参时保持问题和资料不变，只改变一项。

| 子功能 | 更具体的含义 | 使用方法 |
| --- | --- | --- |
| 语义与关键词混合 | 同时利用表达含义与字面词 | 先用默认值；型号和代码问题比较精确命中情况 |
| 相似度阈值 | 过滤相关性不足的候选 | 太高可能漏掉答案；太低可能混入无关内容 |
| 重排序候选数 | 先取出多少候选再排序 | 应不小于最终返回数量；不是最终给模型的片段数 |
| Top N | 最后取多少相关片段 | 只增加数量可能引入噪声并增加上下文 |
| 重排序模型 | 进一步判断问题与片段的相关程度 | 配好 Rerank 模型再启用，比较耗时与命中 |
| 元数据过滤 | 先限制资料属性范围 | 先验证无过滤时能找到，再加过滤比较 |

建议记录 5 个固定问题：原文定义、型号代码、跨段问题、不同版本问题、资料中没有答案的问题。这样更容易看出改动是否有用。

## 18. 铁路问答：按钮与设置逐项说明

### 18.1 助手列表和会话列表有什么区别

**助手**保存模型、知识库和规则；**会话**保存一段聊天。修改助手设置影响后续请求，旧消息不会自动改写成新答案。

在铁路问答列表中搜索并进入助手；卡片更多菜单可重命名、删除。进入后左侧是该助手的会话列表，可以新建、搜索、重命名或删除会话。手机先打开会话抽屉再选择。

批量管理时，进入选择状态 → 勾选或全选当前列表 → 核对数量 → 删除确认；返回箭头用于退出选择。搜索后的全选不能理解成全账号所有聊天。

### 18.2 输入、发送、附件、停止与重新生成

| 子功能 | 作用 | 怎么用 |
| --- | --- | --- |
| 输入框与发送 | 发送这一次问题 | 核对问题和附件后点输入区发送按钮 |
| 附件 | 为当前聊天提供补充材料 | 支持多文件、粘贴截图和拖入图片；上传失败可重试或移除，剩余附件全部就绪后才能发送 |
| 停止生成 | 中止正在输出的回答 | 等停止后再补充或重新提问 |
| 重新生成 | 对已有问题再请求回答 | 回答可能变化，仍需检查引用 |
| 推理 / 研究相关开关 | 请求对应的推理或多步处理 | 取决于模型和后端支持，可能更慢 |
| 联网相关开关 | 通用路径中使用配置的外部搜索 | 需服务配置；铁路主路径按铁路规则关闭联网 |

聊天附件不会因为上传到输入框就自动成为永久知识库文档。以后要持续查询，应按第 7 章入库、解析并绑定。停止只影响当前输出，不会撤销已经发生的模型调用。

注意区分两个纸飞机：**输入区的发送按钮发问题；会话列表标题旁的纸飞机用于分享或嵌入设置。**

### 18.3 引用、复制、反馈、朗读和提示详情

回答的操作按钮常在鼠标移入消息后显示。

| 子功能 | 操作与结果 | 应注意什么 |
| --- | --- | --- |
| 引用 | 点击回答中的来源标记，查看相关片段与文档 | 有引用不等于每句话都有依据，要逐句对照 |
| 复制 | 复制当前消息文字 | 正式记录中同时保留来源和资料版本 |
| 满意 / 不满意 | 提交对回答的反馈，必要时填写原因 | 不会立即训练模型或自动改正下一次回答 |
| 朗读 / 暂停 | 配有可用语音合成时播放答案 | 需要对应模型，文字显示成功不代表语音可用 |
| 提示详情 | 后端返回相关信息时查看组织请求的内容 | 不是每条消息都会出现 |
| 删除消息 | 移除所选消息记录 | 不能用来证明错误内容从所有导出或分享处消失 |

遇到错答时，按“资料是否有 → 检索是否找到 → 引用是否支持 → 回答是否按依据表达”的顺序排查。

### 18.4 聊天设置的基础项

**入口：** 进入助手 → 聊天区域右侧齿轮 → 聊天设置。修改后点底部保存；取消放弃当前未保存修改。

| 子功能 | 含义 | 填写建议 |
| --- | --- | --- |
| 名称、图标、描述 | 帮你识别这个助手 | “A1 教学手册助手”，描述写用途和资料范围 |
| 对话模型 | 组织和生成答案的模型 | 选已测试可调用的模型 |
| 开场白 | 进入对话时的提示文字 | 写适合提出的问题和资料范围 |
| 知识库 | 允许助手检索的资料集合 | 选已完成解析的有关资料；排除无关和过期版本 |

保存后新建会话，用固定问题验证。库被删除或当前账号无权限时，先重新选择有效知识库。

### 18.5 模型参数：影响表达方式，不代替资料

当前界面提供预设或自定义参数。开关通常表示是否明确传入该参数；关闭时可能使用服务默认值，不等于数值为 0。

| 参数 | 通俗解释 | 初学者怎么选 |
| --- | --- | --- |
| 自由度预设 | 一组预先搭配的生成参数 | 先使用默认或偏严谨的预设 |
| Temperature / 温度 | 控制生成时的随机程度 | 规章查阅先保持较稳定设置；低温度也可能答错 |
| Top P | 另一种控制候选文字范围的方法 | 不要和温度同时反复大幅调整 |
| Presence penalty | 影响模型引入新内容的倾向 | 基础问答先默认 |
| Frequency penalty | 减少重复措辞的倾向 | 反复重复时再针对性比较 |
| Max tokens | 限制生成长度 | 太小可能截断；token 不是固定一个汉字 |
| Thinking / 思考模式 | 请求模型默认、开启或关闭思考能力 | 按模型支持选择；不支持时可能被忽略或报错 |

模型参数不改变文档原文，也不能把缺失的手册变出来。开启更多选项可能增加耗时或调用费用。

### 18.6 高级设置：引用、语音、联网、过滤

| 子功能 | 作用 | 使用步骤 |
| --- | --- | --- |
| 显示引用 | 请求答案携带来源 | 打开后用已知问题验证来源可查 |
| TTS / 语音合成 | 将回答转成语音 | 先配置可用 TTS，再测试短回答 |
| 网络搜索 | 用外部搜索补充信息 | 选择支持的提供方，按界面填写凭据；搜索结果需核对 |
| 元数据过滤 | 只查询匹配属性的资料 | 先给文档填属性，再设置条件 |

**铁路助手有服务端固定规则：** 铁路系统提示、引用、无依据回复及关闭联网按铁路处理逻辑执行。通用设置页显示这些字段，不代表改完就能覆盖铁路规则。普通通用助手和自建工作流应分别验证。

### 18.7 普通检索设置：让检索与回答协作

| 子功能 | 是什么 | 怎么用 |
| --- | --- | --- |
| 无结果回复 | 没有合适资料时的回复内容 | 通用助手可写“资料不足，请补充适用版本”；铁路路径固定 |
| 关键词提取 | 从问题中提炼用于查找的词 | 比较开启前后是否保留型号、代码等关键字 |
| 系统提示词 | 给模型规定回答身份、依据和结构 | 通用助手写“仅依据资料，引用不足时说明” |
| 相似度、关键词权重、候选数、Top N、Rerank | 决定取回哪些资料 | 含义和调参方式见第 17.11 节 |
| 跨语言检索 | 帮助跨语言查找相关资料 | 资料与问题语言不同时再试；不保证术语翻译准确 |
| 多轮问题优化 | 结合对话理解“它”“上一条”等省略表达 | 连续追问有用；换主题可新建会话 |
| 动态变量 | 为提示模板设置每次运行需要的输入项 | 变量名、模板引用和实际值保持一致；必填项需有值 |

示例：问完“实名制要求有哪些？”再问“儿童也一样吗？”，多轮优化帮助理解“也一样”指前面的实名制要求。它不能补足资料中不存在的条件。

### 18.8 研究 / Agentic 设置

研究模式让系统按配置进行更多步骤的检索和整理。它不表示模型重新学习了你的文件，也不自动获得实时网络访问。

**决策模型：** 决定处理下一步用的模型；没有单独选择时按系统默认规则处理。**研究模板：** 描述多步处理方法与工具约束；保留模板要求的变量和结构，修改后用简单问题验证。

先用普通模式找到正确片段，再比较研究模式能否改善跨文档整理。研究失败时检查决策模型、模板和实际工具配置，不能只靠增加 Top N。

### 18.9 分享与嵌入网站

进入助手的分享或嵌入入口，按弹窗生成链接或网页嵌入配置。先在另一个浏览器窗口实际打开，检查对方是否能访问、展示哪些内容，以及对应助手是否仍能回答。

分享不等于导出完整系统；链接访问范围按部署配置和实际页面为准。通过外部链接提供服务前，确认所绑定资料允许该受众查看。调整助手或渠道后，也要复查分享入口的行为。

### 18.10 生图、参考图与连续改图

1. 进入已有助手的已保存会话，在输入框输入 `@` 并选择“生图”。
2. 写清主体、数量、构图、风格，以及需要出现在图中的文字，再发送。
3. 生成结束后，图片显示在回答中；刷新后可继续在同一会话查看。
4. 修改上一张时继续选择“生图”，说明哪些内容要改、哪些保持不变。

```text
@生图 横版 2K 高铁旅行海报，标题“向山而行”，一列高铁穿过青山
@生图 把上一张改成夕阳，列车和标题保持不变
```

需要参考图时，先添加 PNG、JPEG 或 WebP 附件，等待上传完成，再发送生图请求。只使用本轮附件进行新创作，与继续修改上一张，是不同的要求；请在文字中明确。需要同时使用上一张和新附件时，上次生成图为参考图 1，附件按上传顺序接续编号。

当前生图服务固定使用 `gpt-image-2.5-sunburst`，默认高质量、原生 2K；可以明确要求横版、竖版、方形或 4K，最长边支持到 3840 像素。编辑未指定新尺寸时沿用上一张。生成仍可能出现文字、数量或细节偏差，需检查结果后继续修改。聊天模式优化建议书里的任务调度等规划尚不能作为当前已上线功能使用。

### 18.11 语音回答与朗读

在已保存会话选择 `@语音` 后，输入问题或想表达的内容：

```text
@语音 高铁和动车有什么区别？
@语音 用温柔轻松的语气说一句晚安
```

语音请求由当前选择的对话模型生成回答，涉及资料依据时结合知识库与会话上下文，再交给本地语音服务发声；不会因为选了语音就自动更换聊天模型。完成后会保留文字、实际返回的引用和可播放音频。

当前本机语音使用 Qwen3-TTS 的 Serena 女声，可以请求调整情绪和语速，实际效果以生成结果为准。已有文字回答旁的扬声器按钮用于朗读该回答，需要已配置可用的默认 TTS。它与发送一次新的 `@语音` 请求用途不同。

### 18.12 唱歌

仍选择 `@语音`，明确写出“唱歌”或“唱一段”，并说明语言、曲风和时长：

```text
@语音 唱一段 20 秒的中文甜美女声晚安歌，轻柔钢琴伴奏
```

当前本机歌曲由 ACE-Step 生成，支持 10～45 秒短歌。系统先合成 Serena 参考语音，再生成音乐，因此首次生成可能比普通说话更慢。语音和唱歌使用不同引擎，不能保证音色完全一致，也不支持保证复刻某个真人声音。

完成后在消息中播放音频，歌词和音频随回答保留。没有明确要求唱歌时，`@语音` 按说话处理。参考语音生成失败会报错，需要排查语音服务后再试。

### 18.13 媒体功能常见问题

| 现象 | 先检查什么 | 怎么处理 |
| --- | --- | --- |
| 提示需要已保存会话 | 是否仍是未保存的聊天 | 先创建或进入已有会话，再选工具发送 |
| 提示未配置生图和语音 | 当前部署的媒体配置 | 请维护人员核对私有配置，不要把 API Key 发到聊天或公开仓库 |
| 普通问答可以，语音或唱歌失败 | 本机配套进程是否运行 | 使用项目启动脚本；维护人员检查本节上方列出的两个本地健康地址 |
| 已上传图片但模型看不懂 | 普通聊天所选模型是否有视觉能力 | 选择支持视觉的模型；`@生图` 参考图走图片编辑服务 |
| 上传失败导致无法发送 | 输入框中是否仍有失败的附件 | 重试失败项，或移除后发送 |
| 改图没有沿用上一张 | 是否同一会话，要求是否明确 | 使用“修改上一张”，写清保留项与修改项 |
| 歌曲生成较慢 | 是否正在首次加载或生成 | 等待本次任务，不要连续重复提交；失败后查看错误再重试 |

项目退出与恢复方法见第 0.1 节。只停止容器时配套进程也会退出，重新使用媒体前应运行本机启动脚本。

## 19. 知识成果：Wiki、树、图谱等分别是什么

### 19.1 五种视图解决不同问题

**入口：** 知识库 → 进入某个库 → 左侧“知识成果”。这是处理结果的阅读区，切换视图不会启动生成。

| 视图 | 用通俗的话解释 | 适合什么任务 | 不应误解为 |
| --- | --- | --- | --- |
| LLM Wiki | 按主题或实体整理的文章集合 | 学习主题、查看交叉链接和原文证据 | 经人工审核的百科全书 |
| 树 / 导航 | 按层级组织章节、主题和摘要 | 先看全貌，再逐层找到具体资料 | 每一层都是原文真实章节 |
| 图谱 / Graph | 展示实体之间提取出的关系 | 查看某设备、概念、责任主体与谁有关 | 系统已验证每条关系真实正确 |
| 思维导图 / MindMap | 用中心主题和分支组织知识 | 课程提纲、主题结构、概念复习 | 设备电路图或业务执行流程 |
| 时间线 / Timeline | 按提取到的时间组织事件 | 梳理资料中有明确日期的变化和事件 | 自动推断出缺失或模糊日期 |

当前页面不把 Skills 作为普通可选成果视图。没有成果时显示空状态是合理情况，先检查生成链路。

### 19.2 怎样实际生成一份成果

用“整理教学资料为 Wiki”为例，先选一份短文档做样本：

1. 到“更多 → 编译算子”，创建或选择 Wiki 类配置，填写整理规则并保存，详见第 22 章。
2. 到“更多 → 数据处理流程”，在可编辑流程中安排文件解析、分块、知识编译器、索引等步骤。
3. 在知识编译器节点选择刚保存的编译算子和可用对话模型；检查上下游输入输出。
4. 保存草稿并发布这个数据处理流程；内置只读流程需要先复制成可编辑流程。
5. 回到知识库 → 分块设置，选择该已发布流程并保存，确认需要处理的文档使用此配置。
6. 在文件列表对样本文档执行解析，等待完成，查看日志是否实际执行了知识编译。
7. 打开知识成果，选择对应视图；核对生成文字和证据。

**成功标志：** 不仅有文档片段，还出现对应的主题、结构或文章内容，并能回查证据。只保存算子、发布空流程或打开成果页都不会自动完成上述工作。

没有结果时依次查：是否绑定正确流程 → 是否已发布 → 编译器是否选择算子与模型 → 文档是否重新处理 → 日志是否成功 → 当前视图是否匹配产物类型。

### 19.3 Wiki 的目录、文章、链接和证据

生成主题后，左侧用于选择文章或查看主题关系；右侧阅读内容。点击内部知识链接可跳转到相关条目，再用页面返回历史继续阅读。

**读一篇文章的顺序：** 看标题 → 看适用范围 → 看主要结论 → 打开证据 → 对照原文。生成的概述与资料直接写出的事实要分清。

实体模式适合“以设备、人物、术语为中心”；主题模式适合“以安全、服务、培训知识点为中心”。具体可用项由所选算子决定。

### 19.4 Wiki 编辑、提交、历史版本、差异与导出

| 子功能 | 使用方法 | 结果与限制 |
| --- | --- | --- |
| 编辑正文 | 在允许编辑的当前版本修改内容 | 修改后还要提交 |
| 取消 | 放弃当前未提交修改 | 不会删除历史版本 |
| 提交 | 填写提交说明，确认本次修订 | 便于追踪改了什么和原因 |
| 历史版本 | 选择以前保存的版本查看 | 历史内容按只读查看；不要假定有一键恢复 |
| 差异对比 | 查看前后增加、删除和修改内容 | 比较文本变化，不自动判断哪版正确 |
| 导出 / 下载文章 | 使用实际文章操作区的导出入口 | 导出的是文章，不是数据库、索引和原件的完整备份 |

示例提交说明：“补充 A1 教学资料的适用范围，修正引用不支持的结论。”资料负责人仍需审核修订；编辑 Wiki 不等于同步改写源文档。

### 19.5 树、图谱、思维导图与时间线怎样看

**树 / 导航：** 从总览逐层展开，选节点看摘要、关联声明和证据。PageIndex、树及 RAPTOR 类结构可能使用树形呈现，理解为不同整理方法，不必把它们当成三份原始资料。

**图谱：** 搜索实体名称，选匹配项后查看关联子图和节点详情；搜不到时先清空关键词，再核对实体是否生成、名称是否不同。关系线表示提取关系，关键结论应查看原文支持。

**思维导图：** 沿主题分支阅读，适合整理学习范围；需要精确条款时返回文档和片段。**时间线：** 核对日期、事件和出处，不要把文档发布日期误当作事件发生日期。

### 19.6 成果页上方的辅助入口

提供这些快捷入口的版本中，“配置知识库”返回处理规则，“解析文档”用于进入资料处理，“查看日志”用于检查执行情况。没有这些按钮时，从知识库侧栏进入配置、文件和日志页面完成同样的检查。

当前知识库侧栏以“知识成果”为普通入口；不必为找旧教程中的单独知识图谱菜单而反复切换账号。

## 20. 更多 → 工作流：把一个任务拆成多个步骤

### 20.1 工作流、数据处理流程、编译算子如何区分

| 名称 | 接收什么 | 做什么 | 产出什么 |
| --- | --- | --- | --- |
| 工作流 | 问题、变量、运行时输入 | 检索、生成、分类、判断、调用工具 | 回复、处理结果或文件 |
| 数据处理流程 | 文档文件 | 读取、切分、提取、知识编译、索引 | 可检索片段和配置好的知识成果 |
| 编译算子 | 编译规则定义 | 告诉知识编译器如何整理资料 | 算子本身是规则；实际成果由处理流程运行生成 |

只想查规章时，不需要先画工作流。工作流适合“先判断问题类型，再检索对应资料，最后按固定格式回答”等明确的多步任务。

### 20.2 列表、新建、模板、导入、标签和删除

进入“更多”选择工作流标签。可搜索名称、按页面条件筛选、通过标签整理；卡片菜单提供名称、标签和删除等管理动作。

**空白创建：** 适合学习最简单流程。**从模板创建：** 保留已安排好的步骤，但仍要选择自己的模型，并为每个检索节点绑定自己的知识库。**导入 JSON：** 读取流程定义，不会把另一账号的密钥、知识库和文档一起搬过来。

模板能创建成功不等于能运行成功。先打开各节点检查红色错误和必填项，再测试。导出也是配置文件，不是系统完整备份。

### 20.3 画布、节点、连线和变量

**画布**是一张步骤图；**节点**做一件事；**连线**表示执行先后；**变量**把上一步结果交给下一步。

```text
开始：接收用户问题
  ↓
检索：到指定知识库找依据
  ↓
Agent：结合问题和检索结果组织回答
  ↓
消息：把需要展示的内容发送给用户
```

点击节点打开配置面板，通过节点菜单添加下一步。连接了两个节点还不够，下一节点的输入也要引用上一步真实输出。例如生成节点应引用检索结果，而不是手工写“检索结果”四个字。

输入框支持变量选择时优先从选择器选，保持类型一致：文字给文字字段，列表给列表处理，文件给文件处理。复制别人的变量名不会自动建立数据关联。

### 20.4 基础、对话和判断节点

| 节点或子功能 | 用途 | 关键配置 | 小例子 |
| --- | --- | --- | --- |
| 开始 / Begin | 接收一次任务的初始输入 | 输入类型、必要变量 | 接收问题和 `device_model` |
| 检索 / Retrieval | 查找知识库内容 | 查询、资料库、阈值、Top N、候选数、Rerank | 查 A1 的 E01 定义 |
| Agent | 让模型结合输入生成或决策 | 模型、指令、引用变量、所用工具 | 只按检索证据回答 |
| 消息 / Message | 输出预设文字或前一步结果 | 文本及变量引用 | 显示答案和资料不足提示 |
| 用户补充 / UserFillUp | 运行中收集缺少的输入 | 字段、类型、是否必填 | 询问未知设备型号 |
| 分类 / Categorize | 让模型把问题分到预设类别 | 类别名称、描述、模型 | 规章类或设备类 |
| 条件分支 / Switch | 按明确条件选择路径 | 比较字段、条件、默认分支 | 型号为空时先补充信息 |
| 注释 / Note | 给维护人员标注设计说明 | 备注文字 | 标记“此分支仅用于教学” |

分类偏语义判断，条件分支偏明确规则。默认分支也要安排结果，避免没有匹配时无输出。检索节点中可见的记忆类配置，不表示本版已经提供独立记忆管理菜单；普通资料检索先绑定知识库。

### 20.5 循环与数据处理节点

| 节点 | 用途 | 配置时要理解的事 |
| --- | --- | --- |
| 迭代 / Iteration | 对列表中的每一项重复步骤 | 输入必须是列表；输出可能仍是列表 |
| 循环 / Loop、退出循环 | 在条件允许时重复执行 | 设置结束条件或限制，检查退出分支 |
| 代码 / Code | 用脚本完成明确计算或转换 | 语言、输入变量、输出结构及执行环境；由懂代码的人维护 |
| 字符串转换 | 拼接或拆分文字 | 分隔符决定怎样切；不是内容理解 |
| 数据操作 | 按条件转换或筛选数据 | 字段类型、比较方式、找不到时如何处理 |
| 列表操作 | 处理一组数据 | 核对输入列表、顺序和输出格式 |
| 变量赋值 | 保存或更新流程变量 | 名称与类型一致，避免误覆盖 |
| 变量聚合 | 合并不同分支的输出 | 确认下游取得的是哪个分支结果 |

例如对三条培训问题逐条检索可以用迭代；只有一个问题时不必先加循环。代码执行需要管理员配置的运行环境，画布能保存不代表运行环境已可用。

### 20.6 外部工具与接口：选择器里的名称是什么意思

下表解释当前工具配置所覆盖的类别。具体是否出现于当前节点选择器、能否调用，以节点面板和实际服务为准；有些提供方需要密钥、可达网络或额外服务。

| 工具或类别 | 干什么 | 需要准备 / 怎么用 |
| --- | --- | --- |
| Tavily Search、Querit Search、Google、Bing、DuckDuckGo | 搜索网页 | 问题或查询词、结果数，按提供方要求填凭据 |
| SearXNG | 使用自建聚合搜索服务 | 可达的服务地址和查询词 |
| You.com、Sofya、Keenable、Search1API Search | 其他外部搜索提供方 | 各自的账号配置与密钥，不能混用 |
| Crawler、Tavily Extract、Querit Contents、Search1API Crawl | 读取指定网页内容 | 网页地址、可访问范围和抓取配置；不是长期自动同步 |
| Wikipedia | 查询百科内容 | 搜索词，结果还需核对来源 |
| ArXiv、PubMed、Google Scholar、BGPT | 查询论文或研究内容 | 主题词及可用服务；不是铁路规章专用数据库 |
| GitHub | 查询代码托管平台相关内容 | 节点实际支持的查询、凭据与范围 |
| Yahoo Finance、WenCai | 查询金融相关数据 | 与业务目标无关时无需配置 |
| ExeSQL | 执行配置的数据库查询 | 连接、查询语句、允许的权限；不同于把文档片段做检索 |
| HTTP / Invoke | 调用指定服务接口 | URL、方法、请求头、参数和响应字段引用 |
| Email | 按配置调用邮件功能 | 邮件服务、收发参数；运行可能真正发送邮件 |
| 文档生成 / DocGenerator | 将内容生成指定格式文件 | 正文输入、格式、输出文件名以及运行依赖 |

外部工具返回的内容不会自动变成你的知识库。铁路工作台助手的固定规则也不会自动附加到任意自建流程，流程中的指令、引用和证据不足处理要自己配置和验证。

### 20.7 保存草稿、检查、运行、探索与发布

1. 配置各节点和变量，在画布检查清单中处理必填项或连接问题。
2. 点击“保存草稿”，确认当前编辑已保存。自动保存也不能代替检查发布版本。
3. 工作流使用“运行”输入测试问题，查看输出；复杂对话可在探索页面实际试聊。
4. 用有答案、无答案、缺字段的情况分别验证，检查节点日志而不只看最后一段文字。
5. 点击“发布”，按确认步骤形成版本；记录本次变化。

**草稿是正在编辑的配置，发布是可引用的版本。** 发布成功不等于所有模型和接口都验证通过。

### 20.8 管理菜单：变量、历史、导出、设置、嵌入

**会话变量**保存同一流程会话中需要复用的值，例如已收集的型号；新会话如何初始化按流程配置检查。**历史版本**用于查看已保存版本及差异，切换操作前核对目标。**导出**保存流程定义，导入后仍需重新绑定依赖。

**设置**管理流程实际提供的运行选项；**嵌入网站**将可对话工作流提供给网页使用。先完成浏览器内测试，再验证嵌入后的输入、输出和访问范围。

**运行日志**用于查看某次执行、各节点输入输出和错误。遇到“最后没有回复”，先看在哪个节点停止，而不是重新创建整个流程。

### 20.9 文档生成：把流程结果变成可下载文件

**入口：** 在工作流中添加“文档生成 / DocGenerator”工具节点。先让前面的步骤产出正文，再在此节点的“内容”中引用该输出；只填文件名不会自动写出报告。

| 子选项 | 怎样填或选择 | 注意什么 |
| --- | --- | --- |
| 输出格式 | PDF、DOCX、TXT、Markdown、HTML | 需要固定版面可选 PDF，需要继续编辑可选 DOCX；纯文字可选 TXT |
| 内容 | 写入文字，或从变量选择器引用前一步结果 | 先运行确认这里拿到实际正文，不能是空值或变量名的字面文字 |
| 文件名 | 例如 `A1-教学学习提纲` | 与正文标题、实际资料版本保持一致 |
| 字号 | 使用面板允许的整数，至少 12 | PDF、DOCX、HTML 显示此类排版项；不要用字号替代章节结构 |
| 页眉、页脚 | 例如资料名称、教学用途说明 | TXT、Markdown 不提供这些排版项 |
| 水印 | 例如“教学演示” | PDF、DOCX、HTML 可配置；不代表文档经过审定 |
| 页码 | 需要时打开 | 当前面板仅在 PDF 格式显示此开关 |
| 时间戳 | 需要区分生成时间时打开 | 这是生成时间，不是所引规章的生效日期 |
| 输出字段 | 查看文件 ID、文件名、类型、大小、下载信息 | 下游节点要引用实际输出；把正文输出给用户不等于同时提供了文件下载 |

一个练习流程是“检索 → Agent 整理学习提纲 → 文档生成 → 消息展示结果”。先用 TXT 验证内容和下载信息，再按需要测试 PDF 或 DOCX 的版面。保存节点后还要运行整个流程，确认文件能打开、中文显示正常、引用和内容没有遗漏；转换服务或字体缺失时请维护人员检查运行环境。

## 21. 更多 → 数据处理流程：文档怎样被整理

### 21.1 内置流程、复制和自定义流程

**用途：** 规定文件进入知识库后如何处理。它处理文件，与接收聊天问题的工作流用途不同。

在“更多 → 数据处理流程”查看现有流程。内置条目是只读预览，需要修改时先复制成自己的流程，再打开编辑。看到不能编辑并不一定是账号故障。

当前数据处理画布不提供与聊天工作流相同的“运行”按钮。验证方式是：**保存并发布 → 知识库绑定 → 解析样本文档 → 看日志和片段**。

### 21.2 节点顺序和输入输出

常见结构如下，具体步骤以你选择的流程为准：

```text
文件 → 解析器 → Token 分块 或 标题分块
     → 可选提取器 / 知识编译器 → 索引器
```

解析器把文件读成结构化内容；分块器整理内容单元；提取器补充关键词等信息；知识编译器生成知识组织结果；索引器让内容能被检索。节点只是出现在画布上不够，还要正确连接和传递输入。

### 21.3 解析器：文件类型与基础选项

| 文件类别 / 选项 | 作用 | 选择方法 |
| --- | --- | --- |
| PDF | 读取页面文字、表格和版面内容 | 先用适合该 PDF 的可用解析方法；扫描件要检查识别效果 |
| DOC / DOCX | 读取 Word 正文和结构 | 关注标题、页眉页脚、表格顺序 |
| 电子表格 | 读取表格内容 | 检查表头与行列关系，不把编号或单位弄丢 |
| PPT | 读取幻灯片文字、图片及表格 | 抽查顺序、表格返回方式和图片 |
| 图片 | 用 OCR 读取图中文字，可结合视觉增强 | 选择内置 DeepDoc 或已配置外部 OCR，按界面可用项选择 |
| 音频 | 用 ASR 把语音转为文本 | 先有可用语音识别模型，核对专有词 |
| 邮件 | 选择读取的邮件字段 | 按需选择发件人、收件人、抄送、密送、日期、主题、正文、附件 |
| HTML | 从网页文件中提取正文 | 检查导航、页脚是否被当正文 |
| 文字 / Markdown / 代码 | 读取文本结构 | 关注编码、标题和内容是否完整 |

当前批量解析路径不应当作已支持视频解析使用；先按实际支持的资料类型操作。

### 21.4 解析器的细分设置

| 子选项 | 是什么意思 | 何时调整 |
| --- | --- | --- |
| 解析方法 | 用哪种可用引擎读取文件 | 对比少量样本质量后选择 |
| 页码范围 | 仅处理指定页面区间 | 去除封面或只试读部分页面，核对起止页 |
| 主要内容 / 标题 / 摘要 / 作者等预处理项 | 从解析内容中关注的部分 | 按节点实际可用项选择，不保证所有格式都有这些结构 |
| 移除页眉页脚 | 排除每页重复的页眉页脚 | 重复内容干扰时使用，检查是否误删条文 |
| 移除目录 | 减少目录重复干扰 | 资料确有目录且支持该选项时使用 |
| 多栏识别 | 处理一页左右多栏的阅读顺序 | 双栏资料乱序时测试 |
| 表格返回形式 | 决定后续拿到怎样的表格表示 | 以字段和值能保持对应为目标 |
| 图片返回形式 | 决定图片在后续内容中的表示 | 需要结合下游能力检查，而非只看缩略图 |
| 语言 | 指定或继承资料处理语言 | 与实际资料相符，核对专业词 |
| 图片 OCR 开关与 OCR 模型 | 识别图中的文字 | 印刷文字与复杂图片分别抽查 |
| 视觉增强、视觉模型、系统提示 | 用视觉模型补充图像理解 | 需要可调用的视觉模型，可能增加成本与耗时 |
| 音频模型 | 执行语音转文字 | 选择 ASR，不是普通对话或 TTS 模型 |

图片文字读取相关配置需要至少保留有效的文字来源，不能关闭必要读取能力后期待得到文字片段。解析选项随文件类型和引擎变化，不是每一份文件都有所有开关。

### 21.5 Token 分块器：按长度和分隔符整理

| 子选项 | 含义 | 使用建议 |
| --- | --- | --- |
| 分隔符模式 / 单块模式 | 按边界切分或尽量作为一个单元 | 长文先分块；单块不适合无限长文 |
| 目标 token 数 | 每块大致长度限制 | 先默认，兼顾条文完整性与检索粒度 |
| 重叠比例 | 相邻块重复一部分内容 | 跨段语义容易断开时小幅增加 |
| 分隔符 | 优先在哪些字符处切开 | 例如换行、中文句号；避免破坏型号代码 |
| 表格上下文 / 图片上下文 | 保留邻近说明文字 | 图表离开说明后无法理解时使用 |
| 图表上下文窗口 | 关联图表周边内容的范围 | 按实际配置项与样本结果调整 |
| 子块开关、子块分隔符 | 在块内部再形成更小单元 | 先明确父子块用途再开启 |

块太小可能把“要求”和“例外”拆开；块太大可能混入多个主题。用真实问题检索，而不是只追求片段数多。

### 21.6 标题分块器：沿章节结构整理

**用途：** 让同一章、节、条的内容尽量保持结构。适合有清晰标题的规章和手册。

主要选项包括层级模式与分组模式、识别到哪个标题级别、标题匹配规则、是否包含标题正文、是否将根块当标题、块长度上限、表格及图片上下文。

**操作例子：** 对有“第一章、第一节、第一条”的资料，选择匹配中文章条的规则 → 设置合适层级 → 解析短样本 → 检查标题是否漏掉、正文是否挂错章节。规则是识别文本的表达式，不是让模型自动理解全部排版；无明确标题时可先用 Token 分块。

### 21.7 提取器：为片段补充哪些信息

| 子功能 | 生成什么 | 关键选项与用法 |
| --- | --- | --- |
| 关键词 | 概括片段中的重要词 | 开关、数量和提示规则；保留型号与代码 |
| 问题 | 片段可能回答的问题 | 开关、数量和提示规则；核对问题确能由片段回答 |
| 摘要 | 内容概述 | 开关和提示词；不把概述直接当原文 |
| 标签 | 从配置的标签体系选标记 | 开关、数量、标签文件；确保标签来源已配置 |
| 元数据 | 结构化属性 | 自定义字段与内置属性；抽查值和类型 |
| 对话模型和生成参数 | 执行上述文字提取 | 先确认模型可用，再逐项开启 |

提取结果也可能出错。先验证一项是否改善检索，再增加其他项，避免一次开启所有功能却无法判断哪一步有问题。

### 21.8 知识编译器与索引器

**知识编译器：** 选择编译算子、对话模型及生成参数，按第 22 章定义的规则整理资料。它不是编译 Go 程序，也不是训练模型。没有配置时不能期待自动生成 Wiki 或图谱。

**索引器 / Tokenizer：** 把处理后的内容写成可以查找的数据。可配置语义向量与全文检索方式、文件名权重、索引正文或问题或摘要等字段。

例如需要按报警代码查找时，字面词索引很重要；语义检索帮助查“过热提示”与相关描述。文件名权重只影响文件名信息参与检索的方式，不会修正文档中错识别的数字。

### 21.9 保存、发布、绑定、重新解析：一次完整练习

创建“教学手册处理流程” → 配置解析和标题分块 → 配置索引器 → 保存草稿 → 检查并发布 → 打开教学资料库的分块设置 → 选择该流程 → 保存并确认文档配置 → 解析一份样本 → 核对片段 → 用原文问题检索。

需要知识成果时，再加入知识编译器并重复验证。流程改了但旧资料没变，先检查是否仍绑定旧发布版本、文档是否实际重新处理。

## 22. 更多 → 编译算子：定义资料整理规则

### 22.1 为什么需要“编译算子”

你可以把它理解成一份“资料整理作业要求”。比如：读完教学资料，按主题生成文章；提取概念定义；把设备和报警的关系整理出来。

**保存算子只保存规则。** 真正执行由数据处理流程中的知识编译器负责，成果在知识库中查看。它不负责自动判断规章是否现行有效。

### 22.2 新建、命名、类型、描述和全局规则

进入更多 → 编译算子 → 新建或编辑，选择界面实际提供的内置类型，再配置规则。当前编辑界面以所选单个算子为主，不必寻找一个页面同时批量维护许多模板的入口。

| 字段 | 怎样理解 | 填写示例 |
| --- | --- | --- |
| 名称 | 便于在流程中选择的规则名 | “A1 教学资料主题 Wiki” |
| 描述 | 说明适用资料与目标 | “仅用于教学手册，按概念和报警主题整理” |
| 内置类型 | 决定生成哪类结构 | 按目标选择 Wiki、图谱、时间线、树等实际可选项 |
| 全局规则 | 所有提取与整理都需遵守的要求 | “只使用输入依据，保留型号、单位和版本；缺失内容不补写” |

切换类型后重新检查字段，原类型的配置不一定适用于新类型。不要仅修改名称就认为生成类型已变化。

### 22.3 Wiki 模式、蓝图指令和示例

**实体 / 主题模式：** 决定围绕对象还是知识主题组织文章。**蓝图指令：** 说明文章结构、必须包含的内容、证据要求。**示例：** 展示希望的格式，帮助模型理解，不是替真实资料补事实。

示例指令：

```text
按教学主题组织内容。
每个条目包含：名称、定义、适用范围、资料直接支持的要点、来源。
不同型号或版本分开叙述。
资料未说明的条件写“资料未提供”，不补充具体参数。
```

先用一两页样本检查是否按预期生成，尤其核对“例子中的事实”有没有被误写进成果。

### 22.4 实体、关系、概念、声明与字段编辑

各类型显示的结构化区域不同，按实际出现的区域设置。

| 结构 | 代表什么 | 例子 |
| --- | --- | --- |
| 实体 | 可识别的对象 | 某设备型号、某术语 |
| 关系 | 对象之间的联系 | 某报警“属于”某设备型号的资料范围 |
| 概念 | 定义和解释性知识 | “安全保护区”的资料定义 |
| 声明 / Claim | 资料明确表达的一条主张 | 某条文对某主体提出的要求 |
| 字段名称、类型、描述、规则 | 规定应提取什么、用何种格式 | `device_model` 为文本；保留原始型号拼写 |

添加字段后，检查必填项和结构；编辑或删除字段会改变后续产物的形状，已有结果不会因此自动全部更新。来源、主体、定义片段等字段应与所选类型的要求对应。

### 22.5 重分块与树形整理的专用设置

**重分块开关与规则：** 允许按编译目标重新组织输入片段，可能改变参与检索的内容单元。先对样本比较检索，不要只看成果是否更美观。

树 / RAPTOR 类配置还包括：

| 专用选项 | 作用 | 怎么理解 |
| --- | --- | --- |
| 摘要提示词 | 规定层级摘要怎样写 | 保留主题、适用范围和来源关系 |
| 声明提取提示词 | 规定从内容中提炼哪些主张 | 只提取资料支持的内容 |
| 最大 token | 限制生成摘要的长度 | 太短可能丢失条件 |
| 聚类阈值 | 控制相近内容怎样归组 | 与当前算法和资料相关，先默认 |
| 聚类比例 | 控制聚类组织的相关参数 | 用同一份样本比较层级是否合理 |
| 按树叶重分块 | 用树的叶节点组织检索片段 | 可能保留原块但使原块不再参与检索，须验证来源和命中 |

### 22.6 JSON 预览、工作流配置预览与保存

预览让维护者检查生成的配置结构，不是调用模型试运行，也不会生成真实知识成果。保存成功后，到数据处理流程的知识编译器节点选择该算子，再按第 19.2 节处理文档。

检查标准：字段清楚 → 规则保存 → 编译器引用正确 → 文档执行成功 → 结果有证据 → 检索仍符合预期。只看到预览 JSON 不算完成。

## 23. 设置 → 数据源：自动取回外部资料

### 23.1 数据源与上传有什么区别

上传由你手工选文件；数据源按连接配置从外部平台取资料，并可定期同步。它主要解决“资料不断更新，不想每次手工上传”的问题。

**数据源定义、知识库绑定、同步成功、解析完成是四个不同状态。** 来源能连上，也不一定已产生可检索片段。

### 23.2 从创建到可检索的完整步骤

1. 头像 → 设置 → 数据源，添加来源，选择实际平台。
2. 填名称、平台所需的地址与凭据，限制需要读取的目录、站点、仓库、页面或查询范围。
3. 使用连接测试，按提示修复访问或权限问题，再保存。
4. 进入来源详情，核对是否启用、刷新周期和同步状态。
5. 进入目标知识库 → 分块设置 → 关联数据源，选择刚创建的来源。
6. 按需求开启该关联的自动解析；保存绑定设置。
7. 等待同步服务取回资料，在文件列表和来源日志中核对实际文件。
8. 等待解析完成，检查片段并做检索测试。

示例：先只关联一个教学资料目录，确认能同步一份文件；成功后再扩大范围。不要把“连接测试成功”当成已把全部网盘建好索引。

### 23.3 连接字段、周期、启停和删除同步

| 子功能 | 含义 | 填写 / 操作方法 |
| --- | --- | --- |
| 名称、类型 | 区分不同来源定义 | 名称说明平台与资料范围 |
| 地址、Endpoint、服务器 | 从哪里读取 | 填后端可访问的地址；容器中的 localhost 不指向你的电脑服务 |
| Token、密钥、账号、OAuth | 证明有权读取资料 | 使用该平台要求的对应凭据，不同类型不能混填 |
| 路径、前缀、空间、项目、页面 | 限定读取范围 | 先填最小测试范围，再扩大 |
| 启用、开始、暂停 | 控制后续同步 | 暂停不等于删除已经入库的文件 |
| 刷新周期 | 多久尝试同步一次 | 当前字段按分钟填写，不是秒 |
| 超时时间 | 单次操作允许等待多久 | 按字段说明填写秒；太小可能误判网络失败 |
| 同步源端删除 | 源端移除资料后同步清理 | 开启前确认希望删除变化传递到库中 |
| 清理周期 | 检查源端删除的间隔 | 开启删除同步后按分钟配置 |
| 日志和状态 | 实际读取、更新或失败记录 | 检查对象、时间和原因 |
| 解除知识库关联 | 取消这一条来源到库的关系 | 先核对确认框对已有资料的处理，不把解绑当作自动备份 |
| 重建 / 重新处理关联 | 对相应来源关联执行重新同步或处理 | 以当前确认范围为准，完成后检查片段 |

当前来源详情对名称等字段可能限制编辑；需要更换连接目标时核对能编辑哪些项。删除来源前先阅读确认范围，不假定源端资料会被删除，也不假定库内旧资料一定保留。

### 23.8 MySQL、PostgreSQL、BigQuery：数据库资料同步

这些连接器把查询结果整理成资料，再进行解析和检索。它们不等于问答时实时执行任意 SQL，也不保证回答时看到数据库刚发生的变化。

MySQL / PostgreSQL 的常见字段包括主机、端口、数据库、用户名、密码、查询语句、正文列、元数据列、唯一 ID 列、时间戳列、文件扩展名、批大小。

例如有一张已经存在的教学表：

```sql
SELECT id, title, content, device_model, updated_at
FROM teaching_notes
WHERE published = 1
```

把 `title`、`content` 作为正文列，`device_model` 作为元数据列，`id` 作为稳定唯一 ID，`updated_at` 作为更新判断字段。表名和列名只是示例，必须换成真实结构。BigQuery 按自身项目、数据集和授权表单配置。

第一次让维护人员用小范围只读查询验证，确认记录没有重复、正文不为空、时间字段可用，再开启定时同步。需要实时查询业务数据，应另行设计对应工作流与接口。

### 23.9 REST API：列表路径、字段映射和分页

用一个教学接口的示例响应来理解：

```json
{
  "data": {
    "items": [
      {
        "id": "note-001",
        "title": "教学记录",
        "content": "这是一条示例资料正文。",
        "device_model": "A1",
        "updated_at": "2026-11-14T09:00:00+08:00"
      }
    ]
  }
}
```

| 子项 | 示例含义 | 填写原则 |
| --- | --- | --- |
| URL、方法 | 请求接口的位置与 GET / POST 等方法 | 按接口实际约定，不填网页前台地址 |
| Query parameters / 请求体 | 传给接口的筛选条件 | 名称、类型与接口一致 |
| 认证 | 无认证、API 请求头、Bearer、Basic 等 | 只选接口实际要求的方式 |
| Items path | 找到记录列表的位置 | 例中逻辑位置是 `data.items`，按表单要求的路径语法填写 |
| ID field | 每条记录的稳定标识 | 例中是 `id`，不要用每次随机值 |
| Content fields | 哪些字段作为正文 | 例中 `title`、`content` |
| Metadata fields | 哪些字段保存为属性 | 例中 `device_model` |
| 时间戳字段 | 判断记录是否更新 | 例中 `updated_at`，实际格式应被连接器支持 |
| 分页 | 逐页取完记录 | 按接口选无分页、页码、偏移量或游标 |
| 高级限制 | 起始页、每页量、最大页数、延迟等 | 先限制几条验证，避免误取无限范围 |

先测试是否取到一条完整记录，再扩大页数。HTTP 返回成功但列表为空时，重点检查 Items path、筛选条件和分页字段。

### 23.10 同步故障怎么定位

**测试失败：** 查地址、认证类型、平台权限和后端网络。**能连但无文件：** 查范围、文件类型、查询结果和同步服务。**文件已到但不能搜：** 查关联自动解析、任务状态、片段和启用开关。**修改迟迟不出现：** 查刷新周期、时间戳、缓存和最新日志。

平台撤销授权后，网页里保留一条连接配置并不能维持访问。同步还依赖部署人员运行相应同步服务。

## 24. 设置 → 聊天渠道：从外部平台向助手提问

### 24.1 渠道做什么，不做什么

聊天渠道把钉钉、飞书、QQ 等平台接到已配置的助手或工作流，让用户在这些平台里提问。它不是把群消息自动当知识库资料同步进来；那属于数据源。

先在浏览器里验证助手能回答，再接渠道。浏览器中助手报错时，换平台通常不会修复模型和资料问题。

### 24.2 添加、编辑、绑定、解绑和删除

1. 头像 → 设置 → 聊天渠道 → 添加，选择平台。
2. 填平台应用或机器人的实际凭据，按平台要求准备权限、事件或连接方式。
3. 保存渠道配置。
4. 点渠道的链条图标，选择绑定“助手”或“工作流”，再选择具体对象并确认。
5. 查看运行状态，等待已连接后到平台发送简单问题。
6. 对照浏览器测试答案及来源，再做缺资料问题测试。

齿轮用于编辑；链条用于修改绑定；清空绑定选择用于解绑；垃圾桶用于删除渠道配置。凭据保存成功、绑定成功、连接成功、问答成功应分别确认。

绑定一个工作流不会自动获得铁路助手规则；要检查这个工作流自己如何处理证据和未知问题。

### 24.3 常用平台各字段是什么意思

| 平台 | 关键子项 | 如何理解 |
| --- | --- | --- |
| 钉钉 DingTalk | Client ID、Client Secret、Streaming、卡片模板 ID、流内容键 | 来自钉钉应用；开启流式卡片时按实际模板填写，内容键需匹配模板 |
| 飞书 / Lark | App ID、App Secret、域、Streaming | 域选择对应国内飞书或 Lark；不能混用另一应用凭据 |
| 企业微信 WeCom | Webhook 或 WebSocket 模式 | Webhook 按界面填企业 ID、应用 ID、Secret、Token、AES 等；WebSocket 使用对应 Bot ID / Secret |
| QQ Bot | App ID、Client Secret | 对应开放平台机器人应用，非个人 QQ 密码 |
| Telegram | Bot Token | 对应机器人的令牌 |
| Discord | Bot Token，按需 Application ID | 应用与机器人身份及服务权限需一致 |
| Slack | Bot Token、App Token、Signing Secret，按需 User Token | 用途各不相同；按平台应用配置填写 |
| Microsoft Teams | 应用与租户相关配置 | 由组织应用管理者提供对应凭据和授权 |
| Google Chat | Webhook 或服务账号 JSON / 文件等模式 | 选择实际接入模式；单有 Webhook 不应假定已经接通全部入站事件 |
| WhatsApp | 网关地址与二维码 | 先运行配套网关，保存后按二维码完成登录 |

流式输出表示边生成边显示，不会提高资料正确性。平台可能对消息样式、卡片或引用显示有限制，应实际检查接收效果。

### 24.4 其他渠道类型及准备内容

下列渠道在当前目录中有入口，具体字段按添加弹窗提供的配置填写；每项都需要对应平台的实际服务和授权。

| 渠道 | 用途与准备方向 |
| --- | --- |
| ClickClack | 对应消息平台的账号或应用接入配置 |
| IRC | 服务器、身份和目标频道等连接配置 |
| LINE | LINE 消息应用的访问与验证配置 |
| Matrix | Matrix 服务、访问身份和会话范围 |
| Mattermost | 服务地址、机器人访问配置和目标范围 |
| Nextcloud Talk | Nextcloud 服务及 Talk 的认证、会话配置 |
| Nostr | 对应身份与中继等连接配置 |
| Synology Chat | Synology Chat 服务及机器人接入配置 |
| Tlon / Urbit | 对应服务身份与访问配置 |
| Twitch | Twitch 账号、频道及聊天授权 |

| Zalo Personal | 个人账号对应的登录配置，区别于应用接入 |

这些名称不是系统已经代你注册好的账号。某个平台的凭据不能填进另一个渠道。

### 24.5 WhatsApp 网关与二维码

网关是替渠道处理外部连接的额外服务。界面默认地址可能是 `http://host.docker.internal:3005`，它只适用于相应本地部署方式；服务器部署应由维护人员填写真实可达地址。

先确认网关运行 → 保存渠道 → 打开二维码入口 → 在对应客户端扫码 → 等待连接状态变化 → 绑定并测试。二维码出现不代表已登录；扫码后仍等待时检查网关日志和账号状态。

### 24.6 运行状态翻译与排错

| 页面状态 | 中文含义 | 下一步 |
| --- | --- | --- |
| Connected | 已建立渠道连接 | 再发问题确认绑定对象和回复正常 |
| Connecting / Reconnecting | 正在连接 / 重连 | 稍候；持续不变时查网络与凭据 |
| Waiting | 等待运行服务启动 | 由维护人员检查渠道运行服务 |
| QR | 等待扫码 | 完成对应平台登录 |
| Error / Disconnected | 运行错误 / 已断开 | 看具体错误与平台授权 |
| Stopped | 当前已停止 | 检查运行服务和配置状态 |

**能收消息但不回答：** 查是否绑定了有效助手或工作流、模型是否可用。**完全收不到消息：** 查平台事件订阅、机器人范围、网络及运行状态。**只有部分人能用：** 查平台和部署的访问限制。

外部平台用户的访问范围不会因为你在浏览器用个人账号登录就自动完全相同。将助手接入群或组织前，核对其可查询的知识库是否适合该受众。

## 25. 账号、管理后台与当前入口范围

### 25.1 普通用户设置

当前普通设置主要包括模型、数据源、聊天渠道；还可按实际菜单切换主题、查看账号标识和退出登录。主题只改变显示风格，不改变资料和模型。

退出后换账号，看到的个人配置、资料和会话可能不同。记录里空了，先确认当前登录邮箱，不要立刻重新上传全部资料。

### 25.2 管理后台与普通页面的区别

管理员使用部署提供的管理入口和管理账号。前端管理路由与普通工作台不同；9381 通常是 Admin 服务端口，不是让普通使用者直接拿来聊天的地址。

| 功能 | 用途 | 操作重点 |
| --- | --- | --- |
| 服务状态 | 查看后端依赖服务与任务执行情况 | 按名称、类型搜索或筛选，查看状态、地址及详情 |
| 服务 / 执行器详情 | 查看某项服务的具体运行信息 | 用于定位任务不动、连接失败；绿灯不证明问答准确 |
| 用户列表 | 搜索账号和查看启用状态 | 按邮箱核对操作对象 |
| 创建用户 | 管理员分配账号 | 填邮箱和初始密码，按实际部署交付账号 |
| 启用 / 停用用户 | 控制账号是否可继续使用 | 停用不是清空资料 |
| 重置密码 | 帮助用户恢复登录 | 核对对象并完成必要交接 |
| 授予 / 撤销超级用户 | 调整管理权限 | 仅由负责管理的人操作 |
| 删除用户 | 删除账号相关对象 | 先阅读确认范围并确认需要保留的数据 |
| 用户详情 | 看登录、创建、更新等账号信息 | 不等于当前开源版提供全部企业资产管理能力 |
| 代码执行环境设置 | 为工作流代码节点配置运行服务 | 选择可用提供方，填写连接参数，测试并保存 |

代码执行环境的测试连接，只检查对应运行环境，不会同时验证知识库和所有外部工具。非维护人员使用普通问答时不需要先配置这一页。

### 25.3 为什么教程有的菜单，这里却没有

当前注册的普通页面没有独立团队管理、API 密钥管理、MCP 管理、记忆管理和独立搜索应用入口。仓库里存在相关源码或旧文档，不代表当前导航已提供可使用的页面。

白名单、细粒度角色、监控等企业能力也不能当成本开源版本已经可用的普通菜单。如果使用的是另一版本或企业部署，应让部署人员说明相应差异。

### 25.4 四类保存分别影响什么

| 你按了什么 | 实际保存什么 | 还需检查 |
| --- | --- | --- |
| 保存模型实例 | 连接与模型配置 | 测试调用、选择默认模型 |
| 保存知识库设置 | 文档处理规则 | 对已有资料的应用和重新解析 |
| 保存草稿 / 发布流程 | 编辑内容 / 可引用版本 | 依赖绑定、运行或样本解析 |
| 保存数据源 / 渠道 | 外部连接配置 | 绑定、运行状态、实际资料或回复 |

“保存成功”只证明这一步被接受。完成一个功能，要看它最后服务的目标有没有实现。

## 26. 术语速查与对照练习

### 26.1 英文和专业词用普通话解释

| 术语 | 用普通话解释 | 与什么容易混淆 |
| --- | --- | --- |
| LLM / Chat model | 根据输入组织回答的对话模型 | 不等于你的资料库 |
| Embedding | 将内容转换成可比较含义的数字表示 | 不负责直接写答案 |
| Rerank | 把候选资料再排一次顺序 | 不会修正源文档事实 |
| OCR | 从图片中认文字 | 不等于真正理解设备运行情况 |
| ASR | 把语音转成文字 | 与把文字读出来的 TTS 相反 |
| VLM / Vision | 理解图片内容的视觉模型 | 仍可能看错图表 |
| Chunk / 分块 / 片段 | 长文处理后用于检索的单元 | 不一定等于一页或一条完整规定 |
| Token | 模型计算文字长度的单位 | 不是固定一个字或一个单词 |
| Index / 索引 | 供系统快速查找资料的数据组织 | 不是原始文件备份 |
| Prompt / 提示词 | 给模型的要求和上下文模板 | 不是程序权限或事实证明 |
| Metadata / 元数据 | 文档或片段的属性 | 不等于正文随手写的标签词 |
| Top N | 最后保留多少条结果 | 不等于候选总数 |
| Threshold / 阈值 | 筛掉不足某条件的结果的门槛 | 不表示答案正确概率 |
| Endpoint / Base URL | 服务接口地址 | 通常不是服务商网站首页 |
| API key / Token / Secret | 接口身份凭据 | 不同于模型名称，也不能跨平台混用 |
| OAuth | 通过授权流程允许访问某账号内容 | 不是只填普通登录密码 |
| Webhook | 平台把事件送往配置入口的方式 | 单有地址不说明双向聊天已接通 |
| Streaming / 流式 | 生成一点就显示一点 | 不等于生成更准确 |
| Pipeline | 文件处理步骤的组合 | 不同于聊天工作流 |
| Compilation / 知识编译 | 按规则把资料整理为知识结构 | 不等于编译程序或训练模型 |
| JSON | 表示结构化配置或数据的文本格式 | 导出 JSON 通常不是全系统备份 |
| Draft / Publish | 草稿 / 发布成版本 | 保存草稿不等于更新使用中的版本 |

### 26.2 用一份教学资料把功能串起来

下面是可以自己创建的测试材料，全部是假设教学数据，不是实际设备操作依据：

```text
名称：A1 教学演示说明
用途：仅用于练习系统操作
型号：A1
版本：2026-11
正文：
本教学例子中，E01 表示“示例输入数据缺失”。
资料只解释演示代码，不包含设备检修或复位步骤。
资料负责人：教学演示组。
```

1. 把这段资料作为你自己的小文档上传，解析后确认能找到 `E01`。
2. 给文档填写 `device_model = A1` 元数据，用过滤前后相同问题比较。
3. 在检索测试问“这个教学例子中 E01 是什么意思？”，应找到正文。
4. 选择这个库发起问答，打开引用，确认解释来自这段教学材料。
5. 问“实际设备怎么复位？”，应认识到资料没有提供这项依据。
6. 禁用文档后新建会话，重复查找，检查未来检索范围的变化；旧消息仍可能保留旧引用。
7. 重新启用后再查；需要练习知识成果时，按第 19.2 节给这份样本配置知识编译。

这些练习分别验证上传、解析、过滤、检索、问答和停用，能帮助你知道问题到底出在哪个环节。

### 26.3 不同目标用哪条最短路线

| 你的目标 | 最短操作路线 |
| --- | --- |
| 查公开规章 | 配好模型 → 工作台导入 → 等解析 → 选择场景 → 提问并看引用 |
| 查自己的手册 | 建库 → 上传 → 解析 → 检索测试 → 绑定助手 |
| 暂时排除旧版资料 | 文件列表禁用 → 新会话验证 → 核对新版是否可检索 |
| 修复一个错识别的字 | 文件名进入片段 → 双击编辑 → 保存验证 → 同步修订源文档 |
| 生成主题文章 | 编译算子 → 带编译器的已发布流程 → 知识库绑定 → 解析 → 知识成果 |
| 自动更新资料 | 创建数据源 → 测试 → 知识库关联 → 同步与解析 → 检索验证 |
| 做多步问答任务 | 创建工作流 → 绑定模型与资料 → 检查变量 → 运行测试 → 发布 |
| 接到钉钉或飞书 | 浏览器问答通过 → 配渠道 → 绑定助手 / 工作流 → 等连接 → 平台测试 |

遇到问题，先说清“我在哪个页面、点了哪个按钮、希望得到什么、实际显示什么”。例如“知识库里文件已完成，但片段数为 0”，比“系统不能用”更容易找到原因。
