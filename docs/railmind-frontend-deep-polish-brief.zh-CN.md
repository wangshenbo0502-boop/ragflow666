# RailMind 前端深度打磨整改书

> 用途：交给执行 AI 直接完成一轮前端优化。
>
> 核心要求：以工作台第一幕为视觉基准，让后面的第二幕、第三幕、第四幕及所有后续内容都像同一个系统自然延展出来。保留全部功能和数据，不做无必要的大改，不需要反复等待确认。

## 一、整改目标

对现有 RailMind 前端做一次完整但务实的视觉和使用体验优化：

- 让工作台从上到下保持统一的布局、留白、标题层级、控件质感和动画节奏。
- 让工作台、聊天页、知识库、更多页、智能应用和其他页面看起来属于同一个产品。
- 保留 RAGFlow 的产品辨识度，同时通过铁路场景、RailMind 品牌和细节处理形成自己的记忆点。
- 界面更精致、更有展示感，适合大学生创新创业大赛演示。
- 保留所有现有业务能力、入口、数据请求和用户数据，不以美化为理由删功能。

## 二、第一幕作为统一视觉母版

用户提供的第一幕截图是本次整改的主要参考。后续每一幕不需要复制相同文案，但要沿用相同的页面骨架和视觉语言。

第一幕具有以下特征，后续各幕都应延续：

- 左侧是稳定的章节编号、英文标签、简短说明和横向强调线。
- 右侧是主要内容区域，内容有明确的最大宽度和固定的左右起点。
- 标题采用克制的大字号和自然的多行排版，标题、说明、操作区之间有明显但舒服的呼吸感。
- 主要内容不堆成普通卡片墙，而是使用大面积留白、细边框、分隔线和少量强调色建立秩序。
- 选项、标签、输入区和按钮使用统一的高度、边框、圆角、颜色和激活状态。
- 强调色只用于当前选中项、关键按钮、编号和少量状态提示，不要满屏使用。
- 内容区与下一个区块之间要有足够距离，滚动时能感受到章节切换。

### 后续每一幕必须保持一致

第二幕、第三幕、第四幕和后续所有工作台区块都按第一幕的结构延展：

```text
左侧章节信息  +  右侧主要内容
编号/英文标签    标题/说明
短说明/强调线    内容导航或场景选择
                 主要操作区域
                 辅助提示/状态信息
                 与下一幕的留白和分隔
```

可以根据内容使用列表、插画、知识状态、档案来源或其他现有模块，但不要每一幕重新发明一套布局。左侧章节栏、右侧内容起点、内容最大宽度、标题层级、区块间距和分隔线应形成稳定的系统。

## 三、布局要求

### 1. 工作台整体

- 介绍大屏与第一幕之间必须有清晰、可感知的纵向过渡留白。介绍内容结束后不要立刻接第一幕标题或操作区，避免两个区域挤在一起、像同一块内容粘连；同时不要留出大到让用户误以为页面已经结束的空白。
- 这段过渡距离要与工作台后续幕之间的章节间距协调，桌面和窄屏都保持舒适，不要依赖某个固定视口高度制造空隙。
- 第一幕到后续所有幕使用同一套 section 容器、网格和间距变量。
- 每一幕都要有清晰的进入位置、主体区域和结束留白。
- 第一幕与第二幕之间，以及后续各幕之间，保持自然的纵向距离，不能挤在一起。
- 不要出现第一幕精致、后面突然变成普通后台页面的情况。
- 统一内容的左右对齐线，标题、输入框、列表、分隔线和操作区尽量落在稳定的视觉基准线上。
- 桌面端保持开阔，窄屏时左侧章节信息可合理收缩或转为顶部信息，但不要造成横向溢出。
- 不要为了填充空间新增统计卡、复杂侧栏、无意义装饰或重复入口。

### 2. 工作台内容层次

每一幕都应有清楚的阅读顺序：

1. 章节身份：编号、标签和简短说明。
2. 当前主题：标题和一句说明。
3. 当前操作：场景、输入、知识库、列表或主要内容。
4. 当前状态：准备情况、提示、资料数量或辅助信息。
5. 下一步方向：自然的继续浏览、开始对话或进入相关页面。

用户不需要寻找很久就能知道这一幕讲什么、现在能做什么、下一步在哪里。

### 3. 页面统一

- 页面标题不要再出现不必要的句号，例如 `RailMind.`、`铁路问答。`、`铁路知识库。`。
- Logo 和字标要简洁、现代、克制，避免土气、复杂或像临时拼接的图形。
- “返回工作台”不要做成突兀的大按钮，改成与页面标题、面包屑或顶部导航自然关联的轻量返回入口。
- 工作台、知识库、聊天、智能应用和更多页使用统一的标题、页边距、按钮、边框、圆角和状态反馈。
- 不同页面可以有自己的内容结构，但不能各自使用完全不同的字体大小、动画速度、按钮形状和间距体系。

## 四、动画和交互节奏

动画要统一、克制、服务于理解，不追求炫技。

- 每一幕进入时使用相同风格的淡入、轻微位移或分层出现效果。
- 章节编号、标题、说明、主体内容按照稳定的轻微错峰顺序出现，速度和距离在各幕保持一致。
- 滚动到新的一幕时，使用相同的 reveal 逻辑，让用户感到进入新的章节，而不是页面突然跳变。
- Tab、场景选择、折叠区和下拉选择使用统一的激活、过渡和焦点反馈。
- 按钮 hover、按下、禁用、加载和成功状态要清晰，但不要产生明显跳动、弹跳或大面积阴影。
- 保留现有有价值的线稿、知识和档案动效，但统一它们的速度、透明度和出现方式。
- 系统开启减少动态效果时，页面仍然完整可用。
- 不新增磁吸、视差、追随鼠标、过度缩放、持续闪烁等容易分散注意力的效果。

## 五、聊天页

聊天页现有功能和业务行为已经基本合适，重点是降低视觉压迫感：

- 不删减模型选择、模型路由、知识库选择、附件、推理模式、媒体模式、发送和已有能力。
- 不改变消息请求、会话、引用、上传和发送逻辑。
- 处理输入区一排密集小按钮的问题：将相关操作按“输入附件”“知识与模型”“高级能力”等逻辑分组，常用操作更突出，低频操作可以收纳到菜单或次级区域。
- 保留所有入口，但减少同时暴露的视觉噪音，避免用户面对一排难以识别的小图标。
- 统一控件高度、间距、图标大小、悬停提示和键盘焦点。
- 发送按钮和输入区域保持稳定，不因长模型名、长知识库名或状态文本发生错位。

## 六、知识库、更多页和智能应用

- 优先改善信息层级和开始操作的路径，让用户知道从哪里进入、如何创建、如何继续。
- 保留已有列表、筛选、创建、编辑、删除、导入、搜索和权限能力。
- 列表页不要全部变成装饰性卡片；操作密度应适合反复使用，同时有足够留白。
- 智能应用页的返回入口、标题、创建操作和内容列表应与工作台使用同一套页面壳层。
- 空状态、加载状态、错误状态和权限状态要有统一表达，不要每个页面各写一套风格。

## 七、账号与数据安全

- 用户必须可以正常退出当前账号，再登录自己的账号。
- 退出失败时，也要清除本地登录状态并回到登录页，避免用户被锁在旧账号中。
- 知识库、聊天记录和智能应用必须按当前账号显示。
- 不要删除、覆盖、迁移或伪造用户数据。
- 后端、Docker 或数据库未启动导致数据不可见时，保留真实状态并给出明确提示，不用假数据掩盖。

## 八、实现边界

- 优先复用现有组件、主题变量、图标库和布局机制。
- 以现有页面为基础做统一和打磨，不要另起一套平行首页或平行主题。
- 视觉改造可以涉及工作台、全局布局、页面样式和聊天控件，但不要顺手重构无关业务代码。
- 不修改公共 UI 基础库，除非现有组件确实无法满足统一样式；优先通过页面级组合和已有 token 完成。
- 不要不断在 CSS 文件末尾追加大量覆盖规则。找到原规则后直接整理，保证后续维护仍然清楚。
- 不要用全局渐变、玻璃拟态、满屏阴影、过多圆角卡片或大面积装饰圆形替代真正的布局优化。

## 九、执行节奏

请一次性完成一轮主要整改，不需要每完成一个小点就停下来等待确认：

1. 先统一工作台所有幕的布局骨架、宽度、间距、标题和分隔规则。
2. 再统一全局品牌、页面标题、返回入口、按钮和动效。
3. 再处理聊天输入区的控件分组和视觉密度，确保功能完整。
4. 最后快速检查知识库、更多页、智能应用、登录和退出路径。

完成后只做必要的快速检查：

- 运行一次适用的格式、lint、类型检查或构建命令。
- 快速查看桌面和窄屏下是否有明显的遮挡、溢出、错位或无法点击。
- 发现明显问题直接修正，不需要安排多轮视觉评审。

## 十、最终效果判断

完成后的页面应满足以下直观感受：

- 用户滚动工作台时，会觉得每一幕都是第一幕的自然延续。
- 第一幕、第二幕、第三幕、第四幕以及后续内容不会出现风格断层。
- 页面有明显的 RailMind 记忆点，但仍能看出它属于 RAGFlow 体系。
- 视觉更高级、更完整，适合现场展示和演示讲解。
- 用户可以快速理解当前页面和下一步操作，不会被一堆小按钮和突兀入口打断。
- 所有原有功能、账号数据和业务流程仍然可用。
