# 轨知 RailMind

本项目基于 RAGFlow 的 Go 检索与对话能力，改造为铁路知识、客运规则、安全培训和设备故障分析辅助系统。定位是有依据的知识助手，不能代替调度系统、现场作业规程和授权人员。

## 已实现的产品路径

1. 登录后进入铁路工作台，选择安全、客运、设备或培训场景。
2. 在模型设置中配置并启用默认对话模型和嵌入模型。
3. 点击“导入官方铁路资料”，创建当前用户的个人知识库，上传项目内的官方资料存档并提交 Go 解析任务。
4. 等待解析完成，选择有检索片段的知识库。可输入问题或点击示例问题，再进入实际对话页确认发送。
5. 复用真实流式回答、会话历史、引用查看、反馈、文档管理和工作流。资料不足时说明不足；现场故障需要补充设备型号、报警信息和适用规程。

设备场景提供型号、报警提示、发生位置和时间记录。填写内容带入对话，由用户确认发送；不自动补全缺失信息，不把报警现象写成确定故障原因。

桌面保留会话侧栏和设置面板；手机使用会话抽屉与设置抽屉，避免挤压问题输入区域。支持关闭、Escape 返回、切换会话和新建会话；设置底部保留提交入口。

解析就绪要求至少一份文档处于 Go 的 `COMPLETED` 状态且有检索片段，所选知识库也必须有片段。仍在 `RUNNING`、`SCHEDULED` 或 `FAILED` 的文档不能仅凭残留片段数被视为完成。工作台持续刷新任务状态并显示失败原因。

重复导入会根据现有文件跳过上传，已完成及正在执行的解析任务不会重新排队；`UNSTART`、`FAILED` 和 `STOPPED` 可以重试。只向当前用户创建的专用知识库写入，不向同名团队知识库自动写入。

Go 铁路对话在请求级固定领域规则和引用，保留持久化设置。调用方不能用研究模式、联网开关、外部工具或直接提供的 `knowledge` 跳过索引检索；没有检索依据时，临时附件也不能代替知识库证据。铁路会话不走通用 SQL 直接回答路径或纯模型问答路径。界面隐藏相应开关，以及由后端固定的提示词、引用关闭、空回答和动态变量设置，仍保留知识库、模型与检索参数管理。

## 本次精简

## 官方资料

`web/public/railway/manifest.json` 记录原始网址、发布网站、采集时间、正文字符数和完整 Markdown 文件的 SHA-256。导入前校验文件原始字节，校验失败时停止上传。同目录的六份 Markdown 保存正文及来源说明：

| 资料 | 主要用途 |
| --- | --- |
| 铁路安全管理条例 | 安全保护区、铁路安全责任 |
| 铁路交通事故应急救援和调查处理条例 | 应急职责、事故调查 |
| 铁路旅客运输规程 | 旅客运输基本规则 |
| 铁路旅客运输安全检查管理办法 | 客运安检责任 |
| 铁路旅客车票实名制管理办法 | 实名制规则 |
| 铁路设备质量安全监督管理办法 | 设备质量监督与追溯 |

资料来自国家铁路局官方网站，共 38,951 个正文字元。采集日期为 2026-10-12。网页存档不是现行有效性认定，答辩和实际使用前必须核对适用版本。公开法规不提供特定型号设备维修知识，不能据此声称已具备准确设备诊断能力。

刷新资料：

```powershell
node scripts/collect-railway-sources.mjs
```

该命令需要先安装 `web` 依赖，使用 HTML 解析器提取官方正文；找不到正文容器或出现不完整页面时停止，不把错误页导入。刷新同名文件后，应在知识库管理中替换旧文档并重新解析。

## 本地运行

完整 Docker 启动沿用 `docs/ai-local-startup-guide.md`。后端必须选择 Go，即 `API_PROXY_SCHEME=go`；本次后端修改需重新构建 Go 服务镜像才能生效。不要使用旧镜像的成功启动作为新代码验证结果。

```powershell
cd web
npm ci
npm run dev
```

前端默认地址为 `http://localhost:9222`，代理到 Go API 的 `127.0.0.1:9380` 和管理 API 的 `9381`。如果端口被占用，Vite 会选择其他端口，以实际输出为准。

仅有前端服务时无法登录、导入数据库、解析或获取模型回答。仓库包含官方资料存档不等于知识库已经入库，上传不等于解析完成，解析完成也不等于已经通过业务评测。

## 参赛验证

评测题集在 `web/public/railway/evaluation.json`。先人工确认各题适用版本和参考依据，再记录模型、知识库版本、检索参数、引用是否支持结论、无依据拒答、危险操作拒绝、澄清质量及回答耗时。文件只定义待评测案例，没有预填准确率或成绩。

建议建立至少三个对照组：直接模型问答、普通 RAG、铁路专用规则加 RAG。分别报告检索命中、引用正确率、回答可靠性和延迟，并由铁路专业教师复核。本文不提供尚未实际运行的实验结论。

创新展示应围绕铁路场景澄清、证据溯源、版本边界和实际用户反馈。申请试点合作、获得合法设备手册和真实脱敏案例、记录专家评价，比扩大功能数量更有价值。保留原项目许可及第三方归属说明；不能将底层开源引擎声明为团队独立原创。

## 验证边界

2026-10-12 的验证结果：

- 前端生产构建通过；存在大资源包体积告警。Lint 通过，仓库其他模块仍有既有警告。
- 七组前端定向测试共 36 项通过，覆盖资料完整性、重复导入、任务失败和取消重试、部分提交失败、个人知识库归属、铁路对话参数、设备背景组装、解析就绪判断以及既有聊天和设置逻辑。
- Playwright 检查 1440 × 900 和 390 × 844 视口。设备场景填写、场景选中状态、六条来源入口、解析中禁用、失败提示、新对话问题带入、移动端会话抽屉和设置抽屉均通过，提交栏可见，Escape 可关闭，没有页面运行错误或横向溢出。接口使用浏览器测试桩，真实入库验证另见下条。
- Docker 编译镜像中通过 `bash build.sh --test -run 'TestPrepareRailway|TestRailway|TestEmptyResponseApplies' ./internal/service`。覆盖请求策略隔离、外部参数不能绕过证据模式、附件无证据拒答、通用附件行为保留和无知识库路径。
- 使用 LLD 20.1.8，通过 `bash build.sh --go` 编译 Go 服务，并执行新二进制 `--api --help` 输出 API 帮助。帮助命令按现有实现返回 1，不能据此推断服务启动失败；也不能用帮助输出代替数据库与服务联通验证。
- 启动挂载新二进制的 `railmind-go-validation` 容器，`/api/v1/language` 返回 `go`。MySQL、MinIO、NATS、Kvrocks、ClickHouse 和 Elasticsearch 正常运行。在独立验证账户下配置本地 Ollama `bge-m3:latest`，通过真实 Go API 上传六份资料并提交解析，六份均为 `COMPLETED`，合计 101 个索引片段。
- 通过真实 `/api/v1/retrieval` 查询安全保护区和车票实名制核验，分别返回相关条文片段。此结果证明上传、解析、嵌入和索引检索链路可用，不代表问答准确率。
- 使用本地 Ollama `qwen2.5:1.5b` 调用真实 `/api/v1/chat/completions`，针对离开实名查验区后返回的问题取得模型回答及 5 条引用片段，验证检索到生成的链路。小模型回答含需人工复核的表述，引用片段返回不代表每一句都被准确支持，不能作为参赛准确率。
- 完整 Go service 包测试仍存在既有日志初始化和缺失测试资源失败；全仓 TypeScript 检查仍有其他模块既有错误，本次涉及页面和服务未在检查输出中出现错误。

本机前端预览位于 `http://localhost:9223/`，新 Go API 位于 `127.0.0.1:9380`。验证账户和其知识库与用户原账户隔离，凭据未纳入 Git；其他账户可从工作台配置模型并导入资料。运行数据存放在本机服务中，不随 GitHub 源码自动部署。危险操作拒绝、引用支持程度和设备分析质量还需通过题集及铁路专业人员评测；提示词规则不能视为已经证明的安全保证。
