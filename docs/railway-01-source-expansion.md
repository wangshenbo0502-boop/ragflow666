### 0.2 五项具体节约措施

1. **完整阅读一次，后续按变化复核。** 新文档首次仍读完整原件。已完整阅读且有记录的文档，后续提供变动段落、完整所属知识点、必要上下文和来源即可；涉及共同条件时必须包括所有受影响内容。
2. **本地确定性检查一次跑完。** 使用现有 Node.js/PowerShell 工具批量检查哈希、ID、标题、来源位置、重复、token 长度和映射。工具输出只给汇总及失败项，详细结果保存在文件；不要再让模型逐字重算已能确定的相同检查。机器检查不能替代语义、效力或视觉审查。
3. **已有合格审核结果可复用。** 只有原文、正文、所属表头与条件、检查规则均未变化且有对应审核证据时才能复用。只有“字符串覆盖通过”的记录，不得当成“语义通过”的缓存。
4. **保留每批最多5篇，不反复写长总结。** 每批用一个短记录列出变动、证据、状态、下一步，约200～400字足够；复杂阻塞另存必要证据。最终完整验收报告仍必须交付。现有 JSON 登记可继续作为机器主记录，Markdown 表由其生成，不用模型分别重写两套内容。
5. **问题集、来源和模型设置复用。** 已有合格问题不重编；原件缓存和来源核验时间未失效时不重复下载。效力相关新线索或最终时效核验必须处理。保持现有模型和参数；不能通过擅自换弱模型、截断原文或缩短必要回答来节约。

### 0.3 缓存和失效规则

复用证据至少关联：`任务类型、doc_id/知识点ID、原文哈希、输入正文哈希、上下文依赖、规则/脚本版本、审核结果、证据路径、核验时间`。模型任务另记模型及提示词版本；检索任务另记知识库快照、管道、嵌入、重排和检索参数。可放在现有登记表的关联记录中，不新建一套管理系统。

- 单个知识点改动：重新检查该点及其直接依赖，保留其他仍有效的结果。
- 共享表头、表注、适用范围或源版本变化：所有依赖它的知识点失效，不能只改一个示例。
- 生成器规则变化：重跑所有使用该规则的确定性检查；语义影响范围不明时扩大复核，不能假设无影响。
- 文档效力或可检索状态变化：关联的问题预期、引用和源文档切片都要重新核验。
- 缺少哈希、依赖或合格审核证据：视为未检查，不以“以前做过”跳过。

### 0.4 成本记录保持轻量

从下一批起，在现有进度记录中增加一行：`本批模型请求数 / 可获得的输入输出token / 重试数 / 缓存复用项数 / 实际费用（可获得时） / 用时`。包括被调用的生成、审核、嵌入和重排服务，不启动Wiki调用；无法观察的主执行模型成本标“未统计”，不能默认为零。不为记账额外调用模型。

使用已有账单或日志中同模型、同任务量、同质量要求的可比批次比较，目标是后续同等工作量费用约为原方式90%。不同资料难度不可直接按篇数比较，token减少也不能直接当作人民币等额节约。没有可比数据就只报告实际调用与耗时，不另跑一遍原方案制造对照费用。

**预算目标不是硬性删任务开关。** 必须补做的核验照常做；不确定事项保持阻塞。禁止为了显示节约10%修改验收标准或把尚未完成的工作标成通过。

## 3. 第一步：盘点并冻结基线

执行顺序不得颠倒：

1. 查看真实目标知识库的文件列表；若无法访问，检查用户明确指定的资料目录。
2. 记录盘点日期、资料范围、知识库名称和实际 ID。不要将项目代码目录中的所有 Markdown 当成知识文献。
3. 按来源标识、标题、发布机构、版本和正文内容查重。相同内容换文件名、换格式、重复上传均算同一篇。
4. 将目录、空文档、纯摘要、虚构演示数据、Wiki 派生页和无正文链接单列排除。
5. 得到原始文件数量 F0、有效知识文档数 N0、独立来源数 S0，记录三者差异。
6. 冻结 N0。后面不能通过删掉旧文档、改变统计范围、拆分长文档来降低基线或抬高完成率。

本项目 `example/railmind-demo/README.md` 明确说明样例使用虚构设备、人员和编号。这些样例可用于功能测试，不算真实铁路文献。

如果知识库和真实资料目录均无法访问：在 `baseline.md` 写“基线未核验”，列出缺少的入口。可以继续建立模板和来源候选表，但不能填造 N0、声称达到三倍，也不能用演示样例替代基线。N0 为零时，倍数目标没有意义，必须取得具体目标数量后再验收。

### 统计规则

“有效知识文档”是具有独立主题、可核验正文和来源、通过质量检查的资料单元。同一原始文献拆成若干章节文件，统计时仍归入一个资料单元；同一资料同时保存 PDF 和 Markdown，也只计一份。专题汇编保留独立身份，但与其已计数的来源不能重复贡献扩充数量；新出现的独立来源可以计数。

| 指标 | 计算方式 |
| --- | --- |
| 最低总量 | `3 × N0` |
| 优先总量 | `4 × N0` |
| 最低净新增 | `2 × N0` |
| 优先净新增 | `3 × N0` |
| 当前倍数 | `当前验收通过的有效总量 ÷ N0` |

例：如果实测 N0 = 40，最低总量是 120，优先总量是 160，需净新增 80～120。这里的 40 只是计算示例，不是项目实测值。旧资料下线或被替代时，重新计算有效总量，替换版本不算新增。

## 5. 第三步：逐篇补全，而不是堆字数

每篇旧文档都建立一行补全记录，依次检查下列维度。至少补齐所有有来源支持且与主题有关的缺口；已经完整的文档允许保持原长度，并说明检查结果。

| 检查维度 | 具体补什么 | 不允许怎样补 |
| --- | --- | --- |
| 概念 | 定义、术语、对象边界 | 把同一句话换说法写三遍 |
| 原理 | 组成、关系、因果或作用机制 | 凭模型常识增加未经核验的事实 |
| 条件 | 线路、设备型号、工况、适用和不适用范围 | 将局部结论写成全铁路通用要求 |
| 过程 | 原文支持的阶段、依赖关系、输入输出 | 自行补造现场操作步骤 |
| 参数 | 原文数值、单位、比较符号、条件 | 猜测数值、阈值、期限或条款号 |
| 例外 | 限制、例外、反例、需要进一步判断的情况 | 删除“仅、不得、除外、且、或”等关键语义 |
| 案例 | 有出处的背景、现象、证据、结论 | 把虚构案例写成真实事故 |
| 问答 | 基于已有证据可回答的常见问题 | 用生成问答冒充新增文献 |

以“新增可回答的问题和有证据的知识点”衡量单篇增量。不得给所有文档统一强加字数；短条款不需要灌水扩成长论文。短资料缺少独立支撑能力时，应补齐同主题来源或标记局限。

原文引用、整理者解释、研究结论必须明确区分。论文实验结果不能自动转写为现行作业要求；过期资料保留历史版本标识，不默认当作现行依据。效力无法核验时写“待核验”，不得写“现行有效”。

## 7. 分批执行与续跑规则

每批固定最多 5 篇，按 `document-register.md` 中待处理顺序执行：读取原件 → 核验来源 → 补全正文 → 保存 MD → 逐项自检 → 更新登记表。不要一次生成几十篇后再统一检查。

文档登记表至少包含：`doc_id、标题、来源 ID、计数归并 ID、是否计入有效数量、排除原因、原路径、MD 路径、主领域、旧/新增、补全前缺口、补全后可回答问题、状态、复核人/模型、日期`。

状态只能从以下值选择：`待获取、待整理、待复核、待归档、不收录`。只有来源可核验、正文有效、查重通过、无阻塞项的文档才能进入“待归档”。状态不是知识库解析状态，二者分开记录。

每批在 `progress.md` 追加：完成哪些 doc_id、净新增计数、补全哪些旧文档、仍缺多少、哪些来源打不开、下一批 doc_id。失败文档留在待复核队列，继续处理不受阻塞的其他资料，不得悄悄跳过。
